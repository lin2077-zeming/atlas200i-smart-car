
### 0.1 找不到板子 IP 怎么办

**① PC 上（Windows，最省事）** —— 双击 `工具脚本\find_car.cmd`，或：

```powershell
cd 工具脚本
.\find_car.cmd                   # 双击等效
.\find_car.ps1                   # 命令行版
.\find_car.ps1 -Subnet 192.168.31 -Sweep   # 指定网段强制扫描
.\find_car.ps1 -NoProbe          # 只按 MAC 找，快
```

它会按 **MAC 前缀**认板子（`ac:45:ef`=WiFi / `a0:70:b7`=网线），
逐级 fallback：已知 IP → ARP 缓存 → ping 扫全网段，最后 SSH 复核，
直接给出可复制的 `ssh root@<ip>`。

**② 板子上（最可靠）** —— 板子有屏幕，开终端跑：

```bash
bash find_ip.sh                  # 完整网络信息 + 推荐 SSH 命令
bash find_ip.sh --ssh            # 只吐 IP，便于脚本取值
```

**③ 手动扫**（不依赖脚本）：

```powershell
1..254 | ForEach-Object { (New-Object System.Net.NetworkInformation.Ping).SendPingAsync("192.168.31.$_", 900) } | Out-Null
Start-Sleep 6
arp -a | Select-String "a0-70-b7|ac-45-ef"
```

> ⚠️ **ARP 缓存会过期**：扫一次没找到 **≠** 板子没联网（踩过这个坑）。
> 加 `-Sweep` 重扫，或直接在板子上 `bash find_ip.sh`。

### 0.2 连不上时的 NetworkManager 检查（板子上）

```bash
nmcli device status                                   # wlan0 是不是 disconnected
nmcli -t -f active,ssid dev wifi | grep '^yes'        # 连的是哪个 SSID
nmcli connection up A102                              # 手动拉起
nmcli -f NAME,AUTOCONNECT,AUTOCONNECT-PRIORITY connection show   # 看自动连与优先级
```

当前配置（已修好，**重启后不用登录桌面也能连**）：
`A102` 优先级 100（主用）· `HONOR 200` 优先级 10（备用）·
`connection.permissions` 为空（原先 `user:HwHiAiUser` 会导致**必须登录桌面才连网**）

## 1. 🔴 铁律：永远用 `bash run_py.sh <脚本>`，别用裸 `python3`

本板同时装着 **conda 的 Python(3.9)** 和 **系统的 Python(3.10)**，
只有系统那个装了全部语音依赖。裸敲 `python3` 很可能跑到 conda 那个，
报出"缺少 sounddevice"这类**假故障**（跟声卡一点关系都没有）。

```bash
bash run_py.sh env_doctor.py          # 看当前用的哪个解释器、依赖齐不齐
bash run_py.sh env_doctor.py --write  # 不合适就自动挑一个并固定
bash run_py.sh --which                # 只看解析结果
```

## 3. 手动控车 GUI

```bash
bash run_gui.sh              # 默认 PySide6（主界面）
bash run_gui.sh --tk         # 回退 Tkinter（零依赖备用界面）
bash run_gui.sh --no-tts     # 不预加载语音播报（省 5~7 秒启动 + 约 600MB 内存）
bash run_gui.sh --demo       # ★ 离线演示模式：没接小车也能用（语音应答）
bash run_gui.sh --no-llm     # 关掉本地 LLM（听不懂就直接回「没听懂」）

# 指定串口
bash run_gui.sh --port /dev/ttyCAR
```

### 3.0 让它听得懂模糊的话（本地 LLM）

规则解析听不懂时，交给**本地小模型**猜你的意思，并给一句拟人化回复。
（编译/模型安装见《../4.语音模块/本地与云端LLM接入.md》）

```bash
bash run_py.sh llm_engine.py --status          # 环境探测（有没有 cli/模型）
bash run_py.sh llm_engine.py --ask "钱进一米"    # 问一句，看它怎么理解
bash run_py.sh llm_engine.py --selftest        # 内置用例（含"绝不下发动作"）
```

实测（0.5B / 本板）：启动 **4.1s**，首次问答 **35s**，之后 **16s/次**，
命中缓存 **0s**；规则能直接命中的指令 **0s、完全不问 LLM**。

> ⚠️ 它是**增强不是依赖**：`--no-llm` 或模型缺失时，行为与以前**完全一致**。
> ⚠️ **急停/停止绝不经过 LLM**（规则层先命中）—— 这是有断言锁死的安全底线。
> ⚠️ 残留的 `llama-server` 会抢 CPU 拖慢一切：`pkill -f llama-server` 清理。

### 3.1 ★ 没接小车怎么用（离线演示模式）

**人不在实验室、接不上小车时**，用 `--demo` 启动，界面就变成一个**能听会说的对话程序**：

```bash
bash run_gui.sh --demo
```

- 文本指令（含语音识别进来的）**照常解析**并**语音应答**，但**绝不发串口** —— 车不可能动；
- 窗口标题会显示 **`🎤 离线演示中（未接小车）`**，底部「声音输出」行也有橙色提示；
- 也可以在界面左侧「串口连接」面板里**手动勾选「离线演示模式」**（不用命令行参数）；
- 支持的指令见 §3.2；`前进一米` → 播报「开始前进」，`速度200` → 播报「速度200」，
  听不懂 → 播报「没听懂」（好区分"没听懂"和"没反应"）。

> ⚠️ 想**不出声**只测解析：把面板里的 **☑ 动作播报** 取消勾选即可（指令仍会被接受）。
> ⚠️ 离线模式下**急停锁定**依然优先：锁定后连演示模式也拒绝动作，且 `stop` 永远放行。

如果 GUI 里**打不出中文**，先跑：

```bash
bash setup_ibus.sh --check   # 看哪里红
bash setup_ibus.sh           # 一键配置 ibus + 拼音引擎
```

然后重启 GUI。详情见《../4.语音模块/GUI语音交互面板.md》§6.3。
（下拉「常用指令 ▾」点选即填，不依赖输入法，演示时更稳。）

界面里的语音功能（**语音播报 / 语音急停** 面板）：

| 控件 | 作用 |
|---|---|
| ● 播报灯 + ☑播报 / ☑动作播报 | TTS 播报状态与开关 |
| ○ 语音急停灯 + [开启语音急停] | 常开监听「急停/停车/刹车」，命中即停车 |
| 声音输出 | 显示「板载喇叭」；没接小车时显示**离线演示提示** |
| 🔒 急停锁定警示条 | **急停后才出现**，点「解除急停锁定」才能恢复行驶 |
| ☑ 离线演示模式 | 左侧串口面板里，**没接小车也能语音应答** |

> ⚠️ **急停后必须人工点「解除急停锁定」**，车不会自动恢复 —— 这是刻意的安全设计。

通过 SSH 远程启动板子 GUI 的写法见《../4.语音模块/GUI语音交互面板.md》。

## 4. 让小车说话（TTS 播报）

### 4.1 现在就能出声 —— 网络音箱（本板没有喇叭）

```bash
bash run_py.sh tts_serve.py --port 8099
```

然后在 **PC / 手机浏览器**打开（**把 `<IP>` 换成板子当前 IP**：
WiFi 用 `192.168.31.128`，网线用 `192.168.137.100`）：

| 地址 | 用途 |
|---|---|
| `http://<IP>:8099/` | **手动试听**：打字 → 点一下 → 出声 |
| `http://<IP>:8099/listen` | **挂着当"车的喇叭"**（要先点一下「开始收听」）|

> 不确定板子 IP？→ 见 **§0.1**（PC 上跑 `工具脚本\find_car.cmd`）。
> 板子上也可直接看：`ip -4 -br addr show wlan0`

### 4.2 整条链路：语音急停 + 播报（不连小车也能跑）

```bash
bash run_py.sh car_gui_core.py --no-connect --tts --voice --seconds 60
```

对着麦克风说「**急停**」→ 立即停车 + 进入锁定态 + 浏览器念「已急停」。

### 4.3 单句播报 / 查环境

```bash
bash run_py.sh car_gui_core.py --say "已急停"     # 只播报一句，不需要小车硬件

bash run_py.sh tts_engine.py --check              # 依赖 / 模型 / 输出设备
bash run_py.sh tts_engine.py --list-models        # 装了哪些模型、自动选了哪个
bash run_py.sh tts_engine.py --list-speakers      # 音色列表（Kokoro 中文音色是 45~52）
bash run_py.sh tts_engine.py --text "已急停" --out /tmp/a.wav   # 存成 wav
```

### 4.4 音质客观测量（合成 → 用板载 ASR 反听 → 打分）

```bash
bash run_py.sh tts_quality_test.py
bash run_py.sh tts_quality_test.py --speakers 45,47,52   # 挑音色
bash run_py.sh tts_speaker_compare.py                    # 或拼成一个对比 wav 一次听完
```

### 4.5 买了 USB 音箱之后

```bash
bash run_py.sh tts_engine.py --text "已急停" --play
```

> 插上音箱后**网络音箱会自动不再启动**，代码一行都不用改。

## 7. 测试与预检

**不需要硬件**（`test_all_offline.py` 会串起来跑）：

```bash
bash run_py.sh test_all_offline.py --quick   # 最快回归（解释器/逻辑/串口/语音急停）
bash run_py.sh test_all_offline.py           # 全量（含 GUI、端到端、ASR/KWS 预检）

bash run_py.sh kws_preflight.py              # KWS 预检
bash run_py.sh asr_preflight.py              # ASR 预检
```

**需要真硬件**（⚠️ 会让车动，先确认轮子离地或周围空旷）：

```bash
# 急停真机链路：真下位机收到停车帧？真音箱出声？**只发停止帧，车不会动**
bash run_py.sh test_estop_hw.py --port /dev/ttyCAR

# 六轴运动 + 急停切断持续运动 + 锁定态（默认每项 3 秒，别改短）
bash run_py.sh test_motion_hw.py --port /dev/ttyCAR
bash run_py.sh test_motion_hw.py --port /dev/ttyCAR --speed 150 --dur 3.0
bash run_py.sh test_motion_hw.py --skip-cut      # 跳过"持续运动+急停切断"
```

> ⚠️ **测运动必须用 ≥3 秒的窗口**：实测电机起速要约 **2 秒**，
> 用 1.2 秒只会截到爬升段（Vx 只有命令的 0.3 倍，看着像坏了）。
>
> 📌 `test_motion_hw.py` 会打印"左转时实际是逆时针吗"的提示 —— 请**目视确认一次**，
> 不符就把 `car_gui_core.LEFT_RIGHT_SWAP` 改成 `True`。

## 9. 后台服务的启动与停止

```bash
# 启动（后台常驻，日志落 /tmp）
cd ~/car_gui
setsid nohup bash run_py.sh tts_serve.py --port 8099 > /tmp/tts_serve.log 2>&1 &

tail -f /tmp/tts_serve.log     # 看日志
ss -ltn | grep 8099            # 确认在监听

# 停止
pkill -f "tts_serve"
```

> ⚠️ **`pkill -f 脚本名` 在脚本里用要当心**：如果同一条命令行里别处也出现了
> 这个名字，`pkill` 会把执行它的 shell 一起杀掉（开发时踩过，退出码 255）。
> 写成 `pkill -f "[t]ts_serve"` 可以避免自匹配。
