# 控制台 UI 改版方案（方案 A：对话式任务台）

> 项目：大创 · 人机交互智能小车
> 平台：华为 Atlas 200I DK A2（昇腾 310B4）
> 前置阅读：《[远程 Web 控制台](远程Web控制台.md)》《[GUI 语音交互面板](../4.语音模块/GUI语音交互面板.md)》
> 状态：**P0 + P1 + v3 改版已实施，110 项断言全绿（2026-10-28）**；P2 预设已按实测标定制定、等真机复核偏差
> 涉及文件：`car_gui/web_ui.html`（P0 主战场）· `car_gui/car_web.py`（P1 起）· `car_gui/car_gui_core.py`（P1 起）

---

## 一、为什么要改

### 1.1 现有控制台是什么

`car_web.py` + `web_ui.html` 是一套**面向操作员**的远程控制台：状态条、方向盘、速度滑块、急停、
指令框、语音输入、高级折叠区。它对"我自己用"这件事已经做得很好——**42 项回归断言全绿**。

### 1.2 面向用户时暴露的 5 个问题

| # | 问题 | 具体表现 |
|---|---|---|
| 1 | **没有入口感** | 一屏全是操作项，新用户不知道第一步该点哪 |
| 2 | **能力不可见** | 用户不知道能说什么，只能自己想 |
| 3 | **过程不可见** | "听→想→说→动"这条核心链路只在日志里，界面上看不到 |
| 4 | **参数化表达** | 给的是 `mm/s` 和命令值，用户想的是"走多远" |
| 5 | **多步无进度** | 只显示"执行中"，不知道第几步 |

> 第 3 条最要命：**这条链路恰好是大创答辩时最值钱的东西**，但现有界面把它藏进了日志。

### 1.3 关键判断：不用加功能，只改表达

现有 `status()` 已经能给出 20+ 字段，能力是齐的：

| 已有能力 | 数据来源 | 现界面是否呈现 |
|---|---|---|
| 连接 / 端口 | `connected` / `port` | ✅（仅文字） |
| 电压 / 等级 | `voltage` / `volt_level` | ⚠️ 只有数字 |
| 当前动作 | `action` / `action_label` | ✅ |
| 真实速度 | `speed` / `speed_mmps` | ✅（但暴露 mm/s） |
| 急停锁定 | `estop_locked` / `estop_reason` | ⚠️ 弱 |
| TTS / KWS / LLM 状态 | `tts_state` / `kws_state` / `llm_state` | ⚠️ 高级区 |
| 多步计划 | `plan_running` | ⚠️ 只有布尔值 |
| 对话链路 | 仅 `/api/logs` 文本 | ❌ **完全没有结构化呈现** |

## 二、设计定位

> **一句话：用户表达意图，系统负责解释与执行；界面负责把这条链路"演"出来。**

三条原则：

1. **过程优先于控件** —— 先让用户看见"发生了什么"，再给他操作入口。
2. **意图优先于参数** —— 说"走一米"，不说"speed=30, duration=3.2s"。
3. **安全优先于美观** —— 急停永远可见、永远可点，任何状态下都不隐藏。

## 三、信息架构

### 3.1 三区布局（桌面端）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ● 已连接 │ 电量 ▮▮▮▯ 62% │ 语音就绪 │ 云端 AI │        [ 急 停 ]    │  ← 状态条（固定）
├────────────────────────────────────────────────┬─────────────────────┤
│ 对话流（主区）                                  │ 手动控制（次区）     │
│ ┌────────────────────────────────────────────┐ │ ┌─────────────────┐ │
│ │ 14:32 · 多步指令 · 6.2s                    │ │ │        ↑        │ │
│ │  听到   "钱进一米，然后左转三十度"           │ │ │   ←   停   →    │ │
│ │  理解   前进 1.0 米 → 左转 30°  [已纠正]    │ │ │        ↓        │ │
│ │  执行   第 1/2 步完成 · 正在执行第 2 步      │ │ └─────────────────┘ │
│ │  回应   "好的，先前进，再左转" · 已播报      │ │  速度  ──○──── 中   │ │
│ └────────────────────────────────────────────┘ │                     │
│ ┌────────────────────────────────────────────┐ │ 常用任务             │
│ │ 14:29 · 闲聊                                │ │ · 前进 1 米          │
│ │  听到   "你今天状态怎么样"                   │ │ · 原地转一圈         │
│ │  回应   "我很好，随时听候差遣" · 未触发动作   │ │ · 演示路线           │
│ └────────────────────────────────────────────┘ │                     │
├────────────────────────────────────────────────┴─────────────────────┤
│ [ 按住说话 ]  [ 也可以直接打字，例如「往前开一点」        ]  [ 发送 ] │  ← 输入区（吸底）
└──────────────────────────────────────────────────────────────────────┘
```

（示意，实际为浅色扁平风格；原型见 2026-10-27 会话记录）

### 3.2 区域职责

| 区域 | 内容 | 更新频率 | 设计原则 |
|---|---|---|---|
| **状态条** | 连接 · 电量（格+%） · 语音/TTS/LLM 状态 · 急停 | 1 Hz 轮询 | 一行放下；**急停固定右上角**，不随滚动移动 |
| **对话流** | 每次交互一张卡，四段链路 | 事件驱动 | 新的在下（或上），可回溯；卡片可整卡复制（答辩截图用） |
| **手动控制** | 方向键、速度（慢/中/快）、常用任务 | 用户操作 | 应急手段，但**始终可见**（不折叠成抽屉） |
| **输入区** | 按住说话 · 文本框 · 任务预设 | 用户操作 | 语音优先，文字兜底 |

### 3.3 响应式

| 断点 | 布局 |
|---|---|
| ≥ 1024 px | 三区（状态条 + 对话流 + 侧栏），如上图 |
| 720 ~ 1024 px | 对话流 + 侧栏收窄为图标栏 |
| < 720 px | 单列：状态条 → 对话流 → 语音按钮吸底；手动控制收进底部抽屉；急停改为右下悬浮圆形按钮 |

> 手机/平板不是主场景，但**演示时用平板很常见**，所以 < 720 px 必须能用，不能只是"不崩"。

## 四、六个关键设计决策

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| 1 | **对话流做主角，日志退到"高级"** | 用户关心"我说了什么、它怎么理解、做了什么" | 需要新增结构化事件（P1） |
| 2 | **四段链路同时显示**（听到/理解/执行/回应） | 这是项目的技术叙事，也是排障入口 | 卡片信息密度上升 |
| 3 | **纠错显式标注**（"已纠正「钱进」"） | 建立信任；把 LLM 行为暴露在阳光下，而不是偷偷改 | 需要后端给出"纠正前/后" |
| 4 | **速度改"慢/中/快"，mm/s 收进悬停提示** | 面向用户不暴露命令值；熟练用户仍能查到 | 需要一层映射 |
| 5 | **任务预设卡片**（前进 1 米 / 转一圈 / 演示路线） | 降低首次使用门槛；演示时一键出效果 | 预设内容要经过真机验证 |
| 6 | **锁定态整屏降饱和 + 说明"需人工解除"** | 误触发急停后，用户要知道为什么车不动 | 需要新视觉状态 |

### 4.1 决策 4 的映射建议

| 档位 | 展示 | 实际下发 |
|---|---|---|
| 慢 | "慢" | 命令值 `25`（约 0.65 m/s 以下） |
| 中 | "中"（默认） | 命令值 `30`（**实测已接近本车最高速**） |
| 快 | "快" | 命令值 `34`（模型饱和，再高无意义） |

> ⚠️ 现有文档已记录：命令值 **>34 已接近本车最高速**（模型饱和）。
> 所以"快"不是"更快"，而是"本车能稳跑的上限"——文案上不要承诺速度。

### 4.2 决策 5 的预设草案（需真机验证后定稿）

| 预设 | 实际文本（走 `/api/text`） | 备注 |
|---|---|---|
| 前进 1 米 | `前进一米` | 依赖 `cmd_to_mmps` 标定 |
| 原地转一圈 | `左转三百六十度` | 依赖 `turn_degps` 标定；**真机需实测偏差** |
| 演示路线 | `前进一米，然后左转九十度，再前进一米` | 3 步上限内 |

## 五、交互细节

### 5.1 一次交互的完整状态机

```
用户输入（语音/文字/预设）
        │
        ▼
  ┌─────────────┐   失败（没听清/超时）
  │ ① 听到       │──────────────► 卡片显示"没听清，再说一次"+ 重试按钮
  └──────┬──────┘
         │ 文本
         ▼
  ┌─────────────┐   闲聊（无动作）
  │ ② 理解       │──────────────► 只显示"回应"一段，卡片标"闲聊"
  └──────┬──────┘
         │ 动作 / 多步计划
         ▼
  ┌─────────────┐   被拒（锁定/白名单/电压）
  │ ③ 执行       │──────────────► 卡片标红"已拒绝：急停锁定中"
  └──────┬──────┘
         │ 完成
         ▼
  ┌─────────────┐
  │ ④ 回应       │   播报成功/失败都要标（TTS 可能降级）
  └─────────────┘
```

**卡片密度控制**：闲聊只占两行（听到 + 回应）；只有触发动作才展开四段。

### 5.2 急停与锁定态

| 状态 | 界面表现 |
|---|---|
| 正常 | 急停按钮红色实心，右上角固定 |
| 已急停（锁定） | **整屏降饱和 + 顶部红色横条**"已急停 · 需人工解除" + 解除按钮（需二次确认） |
| 解除中 | 解除按钮转 loading，防连点 |
| 断连 | 状态条变灰 + "未连接（自动重连中）"；急停仍可点（本地停车） |

**关键约束**：急停**不经过任何队列**，前端按下立即 `POST /api/estop`，不等状态刷新。

### 5.3 异常态文案（面向用户，不暴露内部术语）

| 场景 | 不要写 | 应该写 |
|---|---|---|
| 串口没插 | `serial open failed: /dev/ttyCAR` | "小车没连上，检查一下线" |
| 低电量 | `volt_level=danger, 10.2V` | "电量过低，请充电（马上要自动保护了）" |
| LLM 超时 | `llm timeout after 60s` | "这句话没太听懂，换个说法？" |
| TTS 失败 | `tts_state=failed` | "我说不出话了（语音合成不可用），但动作照常执行" |
| 急停锁定 | `estop_locked=True` | "已急停，需要手动解除才能继续" |

> 原则：**用户不需要知道是哪个模块坏了，只需要知道"现在能做什么"**。技术细节留在"高级 → 日志"。

## 六、视觉规范

### 6.1 颜色

| 用途 | 值 | 说明 |
|---|---|---|
| 就绪 / 安全 | `#1D9E75` / 浅底 `#E1F5EE` | 连接正常、语音就绪 |
| 进行中 / 主色 | `#534AB7` / 浅底 `#EEEDFE` | 语音按钮、发送按钮、进度 |
| 警示 | `#BA7517` / 浅底 `#FAEEDA` | 低电量、降级运行（离线演示） |
| 危险 / 急停 | `#E24B4A` / 深字 `#A32D2D` | 急停、锁定、拒绝 |
| 文本 | `#2C2C2A` 主 / `#5F5E5A` 次 / `#888780` 提示 | 三级足够 |

**约束**：同一屏不超过 3 种语义色；红色**只用于急停与危险**，不得用于普通强调。

### 6.2 字号与间距

| 层级 | 字号 | 字重 |
|---|---|---|
| 卡片标题 / 状态值 | 14 px | 500 |
| 正文（对话内容） | 13 px | 400 |
| 辅助（时间戳、标签） | 11~12 px | 400 |

- 行高 1.6；卡片内边距 12 px；卡片间距 8 px。
- 圆角：卡片 12 px，按钮 8 px，输入框/胶囊 100 px。
- 边框统一 0.5 px，不用阴影（扁平）。

### 6.3 组件规范

| 组件 | 规范 |
|---|---|
| 急停按钮 | 高 ≥ 36 px，红色实心，白字，**不做成图标**（必须带文字） |
| 语音按钮 | 胶囊形，含录音状态点；按下时点变红并显示电平 |
| 对话卡片 | 白底 + 0.5 px 边框；四段用 11 px 灰色标签左对齐 |
| 任务预设 | 小卡片，一列三个，点击即发送 |
| 状态胶囊 | 圆角 100 px，浅底深字 |

## 七、与现有后端的差距

### 7.1 不需要改后端（P0 可直接做）

- 状态条全部数据 —— `/api/status` 已有
- 方向键 / 速度 / 急停 / 解除 —— `/api/action`、`/api/speed`、`/api/estop`、`/api/estop/release`
- 文本指令与多步计划 —— `/api/text` 已支持
- 任务预设 —— 前端拼文本即可
- 语音输入（按住说话 / 自动聆听 / 电平）—— 已有
- TTS 播报 —— `/api/tts/*` 已有

### 7.2 需要改后端（P1）

| 需求 | 现状 | 改动点 |
|---|---|---|
| **多步进度 k/n** | `status()` 只有 `plan_running` | `_run_plan_locked` 每步写入 `self._plan_step=(i, total)`，`status()` 暴露 `plan_step / plan_total / plan_label` |
| **结构化事件流** | 只有 `/api/logs` 纯文本 | 新增 `/api/events?since=N`，环形缓冲（保留 200 条），字段见 §7.3 |
| **纠错前/后** | 日志里有，但无结构化 | LLM 分支记录 `raw_text` / `norm_text` / `changed` 三个字段进事件 |
| **电量百分比** | 有 `voltage` + `volt_level` | **纯前端映射**，后端不改（见 §7.4） |

### 7.3 `/api/events` 字段草案

```json
{
  "seq": 42,
  "events": [
    {"seq": 41, "ts": 1761500000.1, "type": "asr",   "text": "钱进一米"},
    {"seq": 42, "ts": 1761500000.9, "type": "norm",  "text": "前进一米", "raw": "钱进一米", "changed": true},
    {"seq": 43, "ts": 1761500001.0, "type": "exec",  "action": "forward", "label": "前进", "step": 1, "total": 2},
    {"seq": 44, "ts": 1761500002.4, "type": "tts",   "text": "开始前进", "ok": true}
  ]
}
```

- `type`：`asr` / `norm` / `exec` / `reject` / `tts` / `estop` / `release` / `conn`
- 沿用 `/api/logs` 的 `since` 增量语义；`/api/logs` **保留**给高级面板，不删。

### 7.4 电量百分比映射（前端）

4S 电池：满电 16.8 V，标称 14.8 V，固件 12 V 首次蜂鸣、10 V 硬切。

| 电压 | 显示 |
|---|---|
| ≥ 16.2 V | 100% |
| 14.8 V | 70% |
| 13.5 V | 45% |
| 12.0 V | 20%（黄色） |
| ≤ 10.5 V | 5%（红色，提示立即充电） |

> ⚠️ 锂电池放电曲线非线性，这是**趋势显示**，不是精确电量计。文档与界面都应标注"估算"。

## 九、验收标准

### 9.1 功能验收

- [ ] 新用户不看说明，30 秒内能发出第一条指令（可用性测试，找一个人试）
- [ ] 一次多步指令后，卡片能看到 k/n 进度
- [ ] 纠错时能看到原文与规范化文本，并标出哪处被改
- [ ] 急停在任何滚动位置、任何状态下都可见且可点
- [ ] 断网/关页面 3 秒内自动停车（**现有看门狗，不得破坏**）
- [ ] 手机（< 720 px）能完成"说话 → 看到结果 → 急停"全流程

### 9.2 🔴 回归测试影响（改 UI 前必读）

`test_web_console.py` 对首页 HTML 有 **7 条硬断言**，改版时必须逐条对照：

| 断言 | 要求 |
|---|---|
| `"小车远程控制台" in html` | 页面标题文字必须保留（或同步改断言） |
| `'id="estop"' in html` | **急停元素 id 必须是 `estop`** |
| `'data-a="forward"'` + `'data-a="turn_left"'` | 方向键必须带 `data-a` 属性，值为动作名 |
| `"strafe" not in html` 且 `"左移"/"右移" not in html` | 页面上**任何位置**（含说明文字）都不能出现这三个词 |
| `"锁定持续运动" not in html`、`"纯聊天" not in html` | 这两个文案不能回到主界面 |
| `'tag === "INPUT"' in html` | 键盘监听排除输入框的判断必须保留（否则打字会把车开走） |
| `"c_spd" not in html` | 旧速度控件 id 不得复用 |

**规则**：优先让新 UI 满足这些断言；若确需变更语义（如标题），**同时改断言并在提交说明里写明原因**。

### 9.3 新增断言建议（P1 一并加）

- [ ] 首页不含"mm/s"裸值（面向用户不应出现单位）
- [ ] 急停按钮在 DOM 中位于状态条内（不依赖滚动）
- [ ] `/api/events` 返回的 `seq` 单调递增
- [ ] 锁定态下 `POST /api/action` 被拒（已有，保持）

## 十、明确不做

| 不做 | 原因 |
|---|---|
| 3D 地图 / 轨迹回放 | **没有定位硬件**，画出来是假数据 |

### 12.2 实施中发现的五个真问题

1. **单条 360° 转不满一圈**：`duration_for_angle()` 有 `hi=8.0 s` 上限，
   41.55 °/s × 8 s = **332°**。→ 预设改成「两段 180°」，并把
   `PLAN_MAX_ANGLE_DEG` 从 90 提到 **180**（180° 只需 4.33 s，安全边界没放松）。
2. **90° 被误报"超过上限"**：`round(90/41.552, 2)=2.17 s` 反算 = 90.17°，
   旧代码 `90.17 > 90` 成立 → 加浮点容差 `PLAN_ANGLE_EPS_DEG=0.6`。
3. **`_ensure_web_speaker` 有调用没函数体**：NameError 被 `except` 吞掉，
   表现为「TTS 就绪但浏览器永远没声音」。函数体已补齐，日志会明确报错。
4. **自动聆听抢不到麦克风**（用户报「自动聆听无法使用」）：让位一次不够 ——
   自动聆听是反复开关设备的循环，中间播报一次，`_restore_mic()` 就把 KWS
   拉回来抢麦。→ 新增 `claim_mic()/release_mic()` 长期占用；`status()` 加
   `mic_owner`，界面把语音急停显示成「已让位」而不是"关闭"（这才是用户
   看到"急停已关闭却还是被占"的真相）。
5. **界面谎称「板子没有喇叭」**（用户报）：板子插了 USB 音箱**有**外放，
   而该提示只是"浏览器播放是可选功能"。→ 文案改成中性说法并降级为可选提示
   （主色而非警示黄），同时修掉 `tts_serve` / 核心里的同款错误日志。

### 12.3 验收脚本

`car_gui/verify_presets.py` 把「三条预设到底走多远/转多少」变成一条命令的输出，
并支持填 `MEASURED` 后自动算校正系数。**改预设或改标定后必须先跑它。**

### 12.4 与方案的两处偏离（有意为之）

| 方案原文 | 实际做法 | 原因 |
|---|---|---|
| <720px 急停改「右下悬浮圆形按钮」 | 急停留在**状态条内**（46~52px 圆形） | 状态条不随滚动、永不遮挡输入区；少一层定位风险（悬浮版在极端尺寸下会和「发送」叠） |
| 速度用「慢/中/快」+ mm/s 悬停 | 同，但悬停文案写「约 x 米/秒（估算）」 | 连「mm/s」字面量都避免出现在页面里（§9.3 断言要求） |

### 13.1 顺带修掉的两个细节

1. **「离线：」内部前缀漏到界面**：`run_text_command()` 在演示模式下返回 `"离线：后退"`，

   **「离线演示」小徽标**。
