## 一、本次做了什么

对照《../1.总览与架构/GUI开发研究报告.md》，上一代在 RK3576 + 银河麒麟上做过一版 Tkinter 界面，**只实现了手动控制**（前进/后退/转向/停止、串口连接、指令下发），聊天是假数据、没有接真实模型。

本次在这个基础上重写，范围是**把手动控制这一版做扎实**，并针对新板子解决三个老问题：

| 老版本的问题 | 本次的处理 |
|---|---|
| 直接绑死 Tkinter，界面朴素且难扩展 | **拆成"业务核心 + 界面"两层**，PySide6 和 Tkinter 两套界面共用同一份逻辑，后续接 LLM / 语音不用重写控制部分 |
| `MotionController` 里带 `time.sleep`，从界面线程调用会**卡死界面** | 核心层改用后台定时器实现"走 N 秒"，界面永不阻塞 |
| 速度/动作全靠按钮，没有实时状态 | 增加实时状态面板（三轴速度、IMU、电压、急停标志）与安全钳位 |

**后续已增补**：**语音识别已接入**（见《语音识别-ASR.md》），本次新增了 `asr_engine.py` / `asr_cli.py` 和界面上的「语音输入」面板。
**仍未包含**：LLM 对话、摄像头视觉、TTS 播报。代码里为它们预留了扩展点（见第十一节）。

> ### ⚠️ **板子上完全没有音频硬件（实测重要发现）**
>
> 官方内核**没有编译板载音频子系统**，所以：
> ```
> $ cat /proc/asound/cards
> --- no soundcards ---
> ```
> 内核里 `CONFIG_SND_DESIGNWARE_I2S` / `CONFIG_SND_SIMPLE_CARD` / `CONFIG_SND_AUDIO_GRAPH_CARD`
> **全部 `is not set`** —— 意味着**板载 MIC 也用不了**（不是没插好，是没驱动），HDMI 音频同样没有声卡注册。
>
> **唯一出路是 USB 声卡**，好消息是 `CONFIG_SND_USB_AUDIO=y` 已编译进内核，
> **插上即用、不需要装任何驱动**。
>
> 所以：**没有 USB 声卡 = 语音功能（ASR 录音 + TTS 播放）全部不可用**，但手动控制不受影响。

### 3.4 串口权限（**最容易漏的一步**）

普通用户默认没有权限打开 `/dev/ttyUSB0`，会报 `Permission denied`。

```bash
sudo usermod -aG dialout $USER
# 然后【必须注销重新登录】或直接重启，组权限才会生效
```

验证：

```bash
groups | grep dialout          # 能打印出 dialout 就对了
ls -l /dev/ttyUSB0
python3 -c "import serial; s=serial.Serial('/dev/ttyUSB0',115200,timeout=0.1); print('串口可用'); s.close()"
```

> **不想改用户组？** 也可以临时给设备放权（重启失效）：
> ```bash
> sudo chmod 666 /dev/ttyUSB0
> ```
> 长期方案还是加入 `dialout` 组，或用下面 §4.3 的 udev 规则（一次性把权限也定好）。

### 3.5 可选：把串口固定成 `/dev/ttyCAR`

下位机板载的 USB 转串口芯片是 **CH9102**（据厂商《STM32F407VET6 主板资源分配 V2.4》：
"PA9/PA10 → USART1 → CH9102F 串口"、"PD8/PD9 → USART3 → CH9102F 串口"）。
CH9102 与 CH340/CH343 共用 Linux 的 `ch341` 内核驱动，**同样枚举为 `/dev/ttyUSB0`**
（注意：**不是**原代码里默认的 `/dev/ttyACM0`）。如果同时插了别的 USB 串口设备，设备号会漂移。固定一下更省心：

```bash
cd /home/HwHiAiUser/car_gui
bash setup_serial_udev.sh
```

脚本会自动探测当前插着的串口，读取它的 USB VID/PID，生成 `/etc/udev/rules.d/99-car-serial.rules`，把别名固定为 `/dev/ttyCAR`。之后**把 USB-TTL 拔下再插上**，验证：

```bash
ls -l /dev/ttyCAR
```

卸载规则：`bash setup_serial_udev.sh --remove`

### 4.4 接硬件

```
Atlas 200I DK A2 USB-A①  ──USB-TTL(CH9102)──  STM32F407 主控板
Atlas 200I DK A2 12V 电源  ── 独立供电（不要从板子 USB 口给电机供电）
```

> **更省一个 USB 口的接法（推荐）**：下位机主板上丝印有 **`ROS`** 标记的 Type-C 口，
> 那就是串口3（ROS 通信口）。**直接用一根 Type-C 数据线连到 Atlas 的 Type-C 口**，
> 就可以省掉外置 USB-TTL 模块，也就省下一个宝贵的 USB-A 口。
> 注意此时设备名同样是 `/dev/ttyUSB0`（芯片还是 CH9102）。

插好后在板子上确认串口出现：

```bash
ls /dev/ttyUSB* /dev/ttyACM* /dev/ttyCAR 2>/dev/null
dmesg | tail -5          # 能看内核识别到 ch341 最好
```

> **在 Windows 上先用串口助手验证时**，要装厂商驱动包里的 **`CH9102 USB驱动.EXE`**
> （`../3.硬件与供电/厂商资料/软件和驱动/` 目录下），不要装 CH343 的驱动。

**再用命令行验证一次真实通信**（比开 GUI 排查快得多）：

```bash
python3 car_gui_core.py --port /dev/ttyCAR
```

期望看到实时刷新的 `Vx=... 电压=...`。如果一直显示"等待状态帧"，说明串口通了但下位机没在发数据 → 检查下位机是否上电、波特率是否为 115200、串口线是否接在 STM32 的 USART3(PD8/PD9) 上。

想直接看小车动一下：

```bash
python3 car_gui_core.py --port /dev/ttyCAR --demo
```

### 5.2 急停锁定态（**必读**）

**任何一次急停（语音命中、或界面上的急停按钮）之后，车都会进入「锁定态」：**

- 之后**所有运动指令都被拒绝**（`move()` 直接返回 False，车一动不动）
- **只有 `stop` 例外** —— 锁定状态下仍然可以停车，这是刻意的
- 界面顶部会弹出**红底警示条**，写出锁定原因（例：`语音命中「急停」`）
- 窗口标题也会变成 `🔒 急停锁定中 —— …`，避免被忽略

**解除方式只有一个：点警示条右侧的「解除急停锁定」按钮。**

> 💡 **为什么设计成必须人工解除**：
> 如果是误触发（比如环境里有人说了"停车"），车**不会自己又跑起来**。
> 这对一辆会动的车是安全底线 —— 自动恢复意味着"你还没反应过来它就开始动了"。

## 六、怎么操作

### 6.1 鼠标（最直观）

1. 选串口 → 点「连接」→ 顶部圆点变绿。
2. **按住**「↑ 前进」不放 → 小车前进；**松手** → 自动停。这就是默认的**点动模式**，也是最安全的操作方式。
3. 想让它一直走：勾上「锁定持续运动」，点一下方向按钮，它会持续走，直到你按「■ 停止」或再点别的方向。

### 6.2 键盘（推荐，反应最快）

| 按键 | 功能 |
|---|---|
| `W` / `↑` | 前进（**按住走，松开停**） |
| `S` / `↓` | 后退 |
| `A` / `←` | 左转 |
| `D` / `→` | 右转 |
| `Q` / `E` | 左移 / 右移（**本车为麦克纳姆轮，可用**；四驱/差速/阿克曼/履带车不支持） |
| **空格** | **急停**（任何时候都有效，最高优先级） |
| **F2（按住）** | **按住说话**，松开开始识别（语音功能，见文档 8） |
| `[` / `]` | 减速 / 加速，每次 50 mm/s |
| `F11` | 全屏切换（小屏幕上好用） |
| `Esc` | 退出全屏 |

> 在「指令」输入框里打字时，上面的快捷键不会生效，不会误触发小车。

### 6.3 文本指令（规则解析）

在底部指令栏输入短句，回车发送。**这部分就是将来接 LLM 的挂载点**，现在先用规则实现，覆盖高频表达。

| 说法 | 效果 |
|---|---|
| `前进` / `往前走` | 以当前速度持续前进 |
| `前进一米` | 前进 1000mm（按当前速度自动换算时长） |
| `前进 2 秒` / `往前走两秒` | 前进 2 秒后自动停 |
| `前进200毫米` | 前进 200mm |
| `后退` / `往后倒` | 持续后退 |
| `左转` / `左转90度` / `右转45度` | 转向；带角度时自动换算时长 |
| `左移` / `右移` | 麦轮平移 |
| `速度 200` / `速度调到三百` / `把速度调到 150` | 设定速度 |
| `以100的速度前进` / `以两百的速度后退两秒` | 指定速度 + 动作 + 时长 |
| `快一点` / `慢一点` / `速度快一点` | 加减 50 mm/s |
| `停` / `停止` / `急停` / `别动` / `刹车` | **立即停止** |
| 其他听不懂的话 | 不执行任何动作，日志里提示"没听懂" |

**中文输入方法**：直接用拼音输入即可（ibus 智能拼音）。如果打出来是英文，按 **Super+空格** 或 **Ctrl+空格** 切换中/英。若切了也没用，在板子终端跑：

```bash
bash setup_ibus.sh
```

**常用指令下拉**：如果系统输入法完全不可用，也可以点指令栏左侧的 **「常用指令 ▾」**，选中后会自动填进输入框，再按发送即可。

**已通过 18 项解析回归测试**（中文数字"三百/十五/半"等都能识别）。

## 七、参数调整与标定

打开 `car_gui_core.py`，文件头部有集中配置：

```python
SPEED_MIN = 50          # 速度下限
SPEED_MAX = 500         # 速度上限（⚠️ 这是项目自定的安全值，不是协议限制）
SPEED_STEP = 50         # 加减速步长
DEFAULT_SPEED = 300     # 启动默认速度

VOLT_WARN = 11.0        # 低于此值界面黄色告警（12V 系统留 ~1V 余量）
VOLT_LOCK = 10.0        # 低于此值红色告警；同时是厂商规定的电池安全下限

DEG_PER_SEC_PER_UNIT = 0.375   # ⚠️ 转向标定：旧的估计值，建议改用 0.0573
DEG_PER_SEC_PER_UNIT_RAD = 0.0573  # 理论值（Z 轴角速度 0.001rad/s 换算而来）
```

> **关于 `SPEED_MAX = 500`**：协议本身用 short 传速度，范围可达 ±32767；
> 下位机也不限制目标速度，只有 PWM 限幅。所以 **±500 mm/s 是本项目自定的安全上限**，
> 不是协议约束。若要提速，改大这个值即可，但要先确认底盘机械能承受。

> **关于电压阈值**：厂商《T800S Pro 航模遥控器操作说明书》第 9 页明确写着
> 「电池电压**不能低于 10V**，低于 10V 请停止使用……低于 10V 后再充电容易造成电池损伤」。
> 下位机固件 `Turn_Off()` 也是硬编码 `voltage < 10` 就切断所有 PWM。
> 所以 **`VOLT_LOCK = 10.0` 这条线既是软件告警线，也是电池的物理安全红线**，不要往下调。

### 7.1 必须现场标定的两个系数

| 标定项 | 当前取值 | 怎么校 |
|---|---|---|
| **前进距离** | `duration = 距离(mm) / 速度`（即速度是真实 mm/s） | 让小车 `前进一米`，用卷尺量实际走了多少。若实际是 1150mm，说明速度标称偏小，按比例修正系数 |
| **转向角度** | `角速度(度/秒) = 速度值 × 0.375`（旧值） | 让小车 `左转90度`，看实际转了多少度，反推修正 `DEG_PER_SEC_PER_UNIT` |

> ⚠️ **转向系数的量纲问题（本次核对厂商资料后修正）**：
> 从《12V 控制板使用说明书》第 18 页可以看出，**Z 轴控制量的物理意义是「角速度」，
> 单位是 0.001 rad/s**（原文示例："速度为 0(0.001rad/s)"），而不是 mm/s。
> 因此理论换算应是：
>
> ```
> 角速度(度/秒) = Z控制量 × 0.001 × 180/π ≈ Z控制量 × 0.0573
> ```
>
> 旧值 `0.375` 比理论值大 6.5 倍。**两个值都可能是实际标定出来的有效系数**
> （因为电机响应、负载、地面摩擦都会影响），所以代码里两个常量都保留，
> **请实机量角器实测后决定用哪个**，并在实测后把不用的那个删掉。

> **前进距离系数的初值**来自《../3.硬件与供电/硬件组装.md》的动作映射说明（前进一米 ≈ 300mm/s 跑 3.33s），**是估计值，必须实测校准**。标定结果直接改进这两个常量即可，界面和指令解析会自动跟着变。


### 7.2 界面参数

- 速度档位按钮：`car_gui_pyside.py` 里的 `SPEED_PRESETS`（或 `car_gui_tk.py` 同名变量）
- 界面轮询频率：两个 GUI 里都是 `100`（毫秒）
- 日志条数上限：核心层 `CarController._log = deque(maxlen=600)`

## 八、安全须知（**必读**）

1. **默认点动模式**是有意设计的——松开按钮即停，这是最基本的"死人开关"。**不要为了省事长期开着"锁定持续运动"**。
2. **急停有三重**，任何时候都可用：`空格` 键 → 界面上的红色「■ 停止」→ **物理电源开关/急停按钮**。
   **物理急停永远优先于软件**。软件急停只是方便，不是安全冗余。
3. **低压保护**：下位机在电池 <10V 时会自动锁死电机。界面里电压变红就是这个信号——**立刻换电池**，不要硬撑。
   ⚠️ 厂商文档明确警告：「低于 10V 后再充电，**容易造成电池损伤，无法正常充电**」。
   所以 **10V 不只是"限速线"，是电池的报废红线**，务必提前充电。12V 系统（3S 锂电）满电约 12.6V。
4. **首次上电顺序**：先接好所有线 → 开下位机（STM32）→ 再开上位机（Atlas）→ 等板子启动完（约 1 分钟）→ 再开 GUI。**关掉时反过来：先关 GUI，再关板子。**
5. **⚠️ 下位机开机有 10 秒保护期**：底盘控制器上电后 **10 秒内电机强制失能，且串口1/串口3 一律不接收数据**（等 OLED 左下角由 `OFF` 变 `ON` 才算就绪）。
   这段时间里 GUI 能连上、能发指令，但**小车不会动**——这是正常的，不是程序坏了。**建议上电后先等 10 秒再操作**。
6. **⚠️ ROS 串口控制优先级最高，会"抢走"遥控器控制权**：厂商说明书原文——「在 7 种控制方式中，ROS 的控制优先级是最高的，任意时候串口3 收到数据就强制进入 ROS 模式」。
   所以：**只要 GUI 在发数据，航模遥控器 / PS2 手柄 / 蓝牙 APP 都抢不回控制权**。
   → **调试时请先关掉遥控器发射机**，否则"以为手柄能急停"是危险的误解。真正的急停请用**物理电源开关**。
7. **`Q`/`E` 平移本车可用**（本车确认为麦克纳姆轮 M500_MEC）。四驱/差速/阿克曼/履带车型不支持 Y 轴，那种情况按了没反应是正常的。
8. **不要从开发板的 USB 口给舵机、电机供电**——会拖垮板子导致重启。
9. **程序退出时会自动急停**（关闭窗口或 `Ctrl+C` 都会先发停止指令并连发多次），但仍建议养成手动断电的习惯。
10. **串口断了小车会在 1 秒内自动停**（下位机 100Hz 控制循环每秒检查一次是否收到新指令，收不到就把三轴目标速度清零）。
    本 GUI 以 20 Hz 持续发指令，有 20 倍余量。但**拔线等异常情况仍可能溜车最多 1 秒**，请保持安全距离。
11. **传文件时不要边跑 GUI 边传大文件**——4 核 @1.0GHz，同时干两件事会明显卡顿。

## 九、常见问题排查

### 9.1 启动类

| 现象 | 原因 | 解决 |
|---|---|---|
| `no display name and no $DISPLAY` / `qt.qpa.plugin` | 在 SSH 里跑 GUI，没有图形环境 | 到板子本地终端（HDMI0）或 VNC 桌面里跑；VNC 下先 `export DISPLAY=:1`；或用 §4.5 的「远程启动技巧」 |
| `could not load the Qt platform plugin "xcb"` | 缺 Qt 的 xcb 依赖库，**最常见是缺 `libxcb-cursor0`** | `sudo apt install -y libxcb-cursor0 libxkbcommon-x11-0 libxcb-icccm4`，或直接重跑 `install_deps.sh` |
| **`KeyError: 'green'` 之类，启动即崩** | QSS 模板字符串里的 `%(xxx)s` 占位符在格式化字典里漏了键 | ✅ **已在 2026-09-26 修复**（`car_gui_pyside.py` 第 89 行缺 `green`）。若再遇同类报错，对照模板里的 `%(..)s` 与字典键是否一一对应 |
| **PySide6 装不上（`Could not find a version...`）** | pip 源缺 aarch64 wheel | 见 §3.2 的"PySide6 装失败怎么办"，换腾讯云/官方源 |
| `ModuleNotFoundError: No module named 'PySide6'` | 没装成功 | 用 `python3 car_gui_tk.py` 顶上（零依赖），或按 §3.3 重装 PySide6 |
| `ModuleNotFoundError: No module named 'tkinter'` | 缺 python3-tk | `sudo apt install -y python3-tk` |
| `ModuleNotFoundError: No module named 'car_serial'` | 三个接口文件没传到 `car_gui/` | 按 §4.1 第 2 步补传 |
| `ModuleNotFoundError: No module named 'serial'` | 缺 pyserial | `sudo apt install -y python3-serial`；**不要**在 conda 环境里装 |
| 中文显示成方框口口 | 缺中文字体 | `sudo apt install -y fonts-noto-cjk`，重启 GUI |
| 窗口太大/太小、被截断 | 屏幕分辨率 | 用 `--fullscreen` 启动，或 `F11` 切换 |

### 9.2 串口类

| 现象 | 原因 | 解决 |
|---|---|---|
| `Permission denied: '/dev/ttyUSB0'` | 用户不在 dialout 组 | `sudo usermod -aG dialout $USER` → **注销重新登录**；临时可用 `sudo chmod 666 /dev/ttyUSB0` |
| `[Errno 2] could not open port /dev/ttyACM0` | **设备名写错了**，板载 CH9102 一般是 `/dev/ttyUSB0` | 用 `ls /dev/ttyUSB*` 确认，或跑 `setup_serial_udev.sh` 固定成 `/dev/ttyCAR` |
| 下拉框里是空的 | pyserial 没装，或设备没插好 | `python3 -c "import serial.tools.list_ports as p; print([x.device for x in p.comports()])"`；也可以直接在框里手打设备名 |
| 连上了但状态条圆点是**黄色**（收不到回传） | 串口通了，但 STM32 没在发 24 字节状态帧 | 检查下位机是否上电、是否已烧录正确固件、波特率是否 115200、TX/RX 是否接反 |
| 发指令小车不动，但状态帧正常 | 下位机进了急停/低压锁死 | 看界面「急停标志」和电压；检查 STM32 上的物理使能开关（PD3） |
| 电压显示 0.00 | 状态帧里的电压字段没被填 | 确认下位机固件版本与 `car_serial.py` 的 24 字节解析布局一致 |

### 9.3 行为类

| 现象 | 说明 | 解决 |
|---|---|---|
| 松手后小车还在走 | 你可能勾了「锁定持续运动」 | 取消勾选，或按空格急停 |
| 按 `Q`/`E` 没反应 | 非麦轮车型不支持平移 | 正常现象 |
| 方向按钮点了一下就停 | 默认是点动模式（按下走、松开停） | 想持续走就勾「锁定持续运动」，或用键盘按住 |
| 界面卡顿 | CPU 被占用（4 核 @1.0GHz） | 关掉不用的程序；用 SSH 跑重活，别在桌面会话里跑推理 |
| 走一秒实际走了一秒多 | 电机启动/停止有惯性，且 LLM 无关的定时精度受系统调度影响 | 属正常，需要精确就用编码器闭环（下位机已支持）；或延长时长做标定补偿 |

### 9.4 自测报错

```bash
# 先跑这个，它会明确指出哪一层出问题
python3 selftest_offline.py

# 想覆盖更全（含串口协议、GUI 键盘、端到端），跑这个
python3 test_all_offline.py
```

- 若这里就失败 → 环境/文件问题（`car_serial.py` 是否在位、Python 版本）
- 若这里全过但 GUI 起不来 → 显示环境或 Qt 依赖问题（看 §9.1）
- 若 4 套全过但真车没反应 → **软件没问题，去查硬件**（接线、电源、使能开关、10 秒保护期）

### 9.5 实测确认的"不是问题"

以下几类现象在 2026-09-26 实机验证中确认为**正常行为**，不必排查：

| 现象 | 真相 |
|---|---|
| 日志打印 `没有找到录音设备` | 板子**没有任何音频硬件**（内核未编译 SoC 声卡），插 USB 声卡即可 |
| 日志打印 `打开串口 /dev/ttyCAR 失败` | 小车没接，或 udev 规则还没配。属预期 |
| 日志末尾有 `onnxruntime cpuid_info warning: Unknown CPU vendor` | 昇腾 CPU 不被 onnxruntime 的 CPU 探测库识别，**无害**，不影响推理 |
| 启动时打印 `This plugin does not support propagateSizeHints()` | offscreen/部分平台的 Qt 提示，**无害** |
| `npu-smi info` 显示 `310B4` | **正确**。310B4 = 8T 档，310B1 才是 20T |
| GUI 启动后日志没有"语音模型已就绪" | 模型要在界面里**手动点「加载模型」**才加载，启动时不自动加载 |

## 十、与上一代（RK3576 / 银河麒麟）的对照

| 项 | 上一代（麒麟） | 本次（Atlas / Ubuntu 22.04） |
