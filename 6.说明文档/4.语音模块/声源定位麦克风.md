# 声源定位麦克风（HK-QXMIC-V3.0）

> 前置阅读：《[语音识别（ASR）](语音识别-ASR.md)》《[语音急停（KWS）](语音急停-KWS.md)》
> 状态：驱动 + 文档就绪；**USB 音频已实测通过（板上枚举为 `CF-IC DOV`）**；**串口坐标待接 TTL 线**。
> 文中标「**待真机验证**」的项仍未确认。

**先记三句话**：

1. **UAC1.0 免驱 USB 声卡（采集）+ 1M 波特率 TTL 串口（12 方位坐标）** 二合一的圆形阵列麦。
2. 本车**只接接口 1（USB）和接口 3（TTL）**：USB、TX→RX、GND→GND 共 3 根线，**TTL 的 3V3 不要接**。
3. 最大的坑是**设备名**：CH340 与小车 CH9102 会抢 `/dev/ttyUSB0`，必须 udev 固定成 `/dev/ttyMIC`。

---

## 一、这是什么

好凯盛 **HK-QXMIC-V3.0** 全向声源定位阵列麦克风模组：一边当 USB 麦克风，一边用 TTL 串口每 200~300 ms 吐一个「声音来自第几方位」的短帧。

| 项 | 参数 |
|---|---|
| 型号 / 形态 | 好凯盛 HK-QXMIC-V3.0 全向声源定位阵列麦；圆形，直径 **77 mm**，**5 MIC** 环形阵列 |
| 供电 | **5 V ±5% / 200 mA**（不带喇叭时 1 W max） |
| 音频接口 | **UAC1.0 免驱声卡**，**48 kHz @ 16 bit**，USB2.0；**实测 44100 / 48000 均可**（2ch）；Linux/Ubuntu 免驱 |
| 拾音 | **360°** 全向，有效距离 **≤ 8 m** |
| 定位 | **12 个方位**（每 30°），角度精度 **±15°** |
| 音频处理 | 内置 **AEC / ANC / AGC / SE** 降噪 |

> 参数出自 `../7.参考资料/声源定位麦克风/` 三份原始资料（见 §8.1），未做二次推测；**实测值见 §3.3**。

## 二、接口与接线

模组共 6 个接口（接口号见图纸《接口说明.jpg》）：

| 接口 | 丝印/形态 | 作用 | 本车是否用 |
|---|---|---|---|
| **1** | USB（PH5PIN 1.25 mm） | **供电 + 音频**，插设备 USB 口；标配 1.6 m 线 | ✅ **必接** |
| **2** | 喇叭 2PIN1.25（L+ L-）/ 4PIN1.25 双喇叭 | 单/双喇叭，总功率 ≤5 W（**带功放版才有**） | ❌ 不用（播报走现有 USB 声卡） |
| **3** | TTL 串口（丝印 **3V3 / TX / RX / GND**） | 坐标输出：**板 TX → 串口 RX、GND → GND**（3V3 不接） | ✅ **必接** |
| 4 | 3.5 mm 功放输入并联 | 回采（回声消除） | ❌ 暂不接 |
| 5 | 并联喇叭线 | 回采（不带功放版用） | ❌ 暂不接 |
| 6 | 外部 3.5 mm 功放 | 带功放版接外部功放做回声消除 | ❌ 暂不接 |

**本车 3 根线**（接口 3 厂商**不配线**，需自备 USB-TTL（CH340/CH343）+ **PH1.25 4pin 线**）：

```
        ┌──────────── HK-QXMIC-V3.0 ────────────┐
开发板  │ 接口1 USB ──(标配 1.6m 线)──→ USB-A   │  供电 + 音频（UAC1.0 声卡）
USB 口  │ 接口3 TX  ───────────────→ USB-TTL RX │  坐标帧（1M 8N1）
        │ 接口3 GND ───────────────→ USB-TTL GND│  必须共地（3V3 不接）
        └────────────────────────────────────────┘
```

> ⚠️ **3V3 不要接**：接口 3 丝印是 **3V3 / TX / RX / GND**，供电由接口 1 负责，本车只接 **TX + GND**。
> ⚠️ **TX/RX 交叉**：模块 TX → USB-TTL RX；接成 TX→TX 一个字节都收不到。

## 四、串口协议与坐标解析

### 4.1 帧格式（厂商操作说明 + 截图实测）

**1,000,000 baud，8N1，无流控**；设备每 **200~300 ms** 吐一帧，共 4 字节：

| 字节 | 值 | 含义 |
|---|---|---|
| 0 | **`0x55`** | 帧头 1 |
| 1 | **`0xAA`** | 帧头 2 |
| 2 | `coord` = **0~11** | 方位号（sector） |
| 3 | `0xFF - coord` | 校验和（**不是 CRC**） |

例：`55 AA 05 FA` → sector 5，校验 `0xFF-0x05 = 0xFA` ✅。

**必须扫描式解析**：串口流里**混有其它调试字节**（如 ASCII `iGo-CMD timeout`），不能假设「每 4 字节一帧」。
做法：找 `55 AA` → 取第 3 字节 → 用第 4 字节校验 → 不匹配就**丢 1 字节继续找**。
`qxmic_locator.FrameParser.feed()` 已按此实现，并覆盖分片、粘包、噪声、非法 coord（>11）（见 `test_qxmic_locator.py`）。

### 4.2 12 方位

sector *k* 覆盖 **[180+30k, 210+30k)°**，中心角 **`(195+30k) mod 360`**（厂商口径「方位 180° 对应 00」）：

| sector | 覆盖角度 | 中心角 | 参考方向（**假设** 0°=车头、逆时针增大；**待真机标定**） |
|---|---|---|---|
| 0 | 180°~209° | **195°** | 后 |
| 1 | 210°~239° | **225°** | 右后 |
| 2 | 240°~269° | **255°** | 右 |
| 3 | 270°~299° | **285°** | 右 |
| 4 | 300°~329° | **315°** | 右前 |
| 5 | 330°~359° | **345°** | 前 |
| 6 | 0°~29° | **15°** | 前 |
| 7 | 30°~59° | **45°** | 左前 |
| 8 | 60°~89° | **75°** | 左 |
| 9 | 90°~119° | **105°** | 左 |
| 10 | 120°~149° | **135°** | 左后 |
| 11 | 150°~179° | **165°** | 后 |

```
                 0°（车头）
        k6 15° ╱           ╲ k5 345°
      k7 45°  ·             ·  k4 315°
     左 90° ───── [ 车 ] ───── 270° 右
      k8 75°  ·             ·  k3 285°
        k9 105° ╲         ╱ k2 255°
          k10 135°  k1 225°
          180° 后：k11 165° / k0 195°
```

> ⚠️ **方向列是假设值**：厂商只给「方位号 ↔ 角度」，装车后的前后左右需标定（§8.2）。

### 4.3 三个必踩的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **1M 波特率** | 用默认 115200 → 乱码/解不出帧 | 显式 `--baud 1000000`；`stty` 手动调试时别忘了 |
| **串口混流** | 固定长度 `read(4)` 读 → 帧错位、校验频繁失败 | 扫描式解析（找 `55 AA` + 校验），别按时长切 |
| **设备名冲突** | CH340 与 CH9102 都枚举 `ttyUSB*`，插拔顺序一变就串台 | udev 固定 `/dev/ttyMIC` 与 `/dev/ttyCAR`，程序里不写 `ttyUSB0` |

## 六、与本项目的集成

### 6.1 当 ASR / KWS 的麦克风

这块是标准 UAC1.0 声卡，插上后 `arecord -l` 多出一项 `DOV`：

| 选设备方式 | 操作 |
|---|---|
| **GUI（推荐）** | 语音面板「麦克风」下拉选 `DOV` → 会被**记住**（`~/.config/car_gui/mic_device.txt`，换口/重启不丢） |
| 命令行 | `python3 car_gui/asr_cli.py --list-devices` 看设备号，再 `--device N` |
| 自动打分 | **只插阵列麦时**：设备名 `DOV: USB Audio`，`guess_input_device()` **自动选中**（实测）。**但同时插了老的单声道无线麦时会被老麦抢走**——打分规则偏爱单声道纯采集设备（老麦 115 分 vs 阵列麦 95 分），实测自动选了 `[0] USB2.0 Device`，此时**必须手动选 `DOV`** |
| 卡号会变 | 直插是 `card0`、经 USB Hub 是 `card2`；**别把索引写死**，用 GUI 记忆或每次 `--list-devices` 现看现选 |

- **采样率**：**实测 44100 / 48000 均可**；项目按 48 kHz 采集、自动重采样到 16k，**无需 16k 适配**（`_RATE_CACHE` 记住可用值）。
- **AEC 回采**：模块自带 AEC，但 **USB 侧只有采集端点、没有播放端点**（实测），回采要另接接口 2/4/5/6；本车播报仍走另一块声卡。⚠️ **接法与真实音量下的 AEC 效果待真机验证**。

### 6.2 声源方向控车（`qxmic_demo.py`）

```bash
bash car_gui/run_py.sh qxmic_demo.py --simulate              # 无硬件看效果：大字箭头 + 12 格罗盘
python3 car_gui/qxmic_demo.py --port /dev/ttyMIC             # 真机看方向（不动车）
python3 car_gui/qxmic_demo.py --port /dev/ttyMIC --drive     # 联动 CarSerial（默认 ttyCAR）—— 真会动！
```

**安全限制（`--drive` 才有，均硬编码上限）**：

| 限制 | 值 |
|---|---|
| 默认行为 | **dry-run**：只打印，不发串口 |
| 速度 | **≤ 150 mm/s** |
| 单次动作时长 | **≤ 1.2 s**，到时限自动停 |
| 中断 | **Ctrl-C 必停**（`finally` 里必发停车帧） |

> ⚠️ 第一次 `--drive` 必须**架空车轮**：它只是「朝声源转一下」，不是导航闭环。

### 6.3 和「语音急停 / 全双工」方案的关系 —— **假设被实测推翻**

现状（详见《[播报期间语音急停保持有效——全双工改造方案](播报期间语音急停保持有效-全双工改造方案.md)》）：采集（PCM2902）与播放（SPACETOUCH）是**两块 USB 声卡**、挂同一颗 xHCI，播报时开麦失败（`-9999` / `dmesg` `-28 ENOSPC`）→ 只能分时让位 → **播报期失聪**。

**2026-11-05 实测**：本模块 USB 侧**只有采集、没有播放端点**（`aplay -l` 里没有它）⇒ 「一块设备同时采集 + 播报，从根上消掉让位窗口」这个假设**在本版本 USB 侧不成立**，播报仍须靠另一块声卡/功放。

**补充实测（同日，双设备对比）**：把 DOV（阵列麦）与原 SPACETOUCH（播放）同时插上，`arecord -D plughw:0,0` 正常，但并行 `aplay -D plughw:1,0` **一律失败**（`aplay: set_params:1416: Unable to install hw params`，`dmesg` 反复 `usb 3-1.1: Not enough bandwidth ... usb_set_interface failed (-28)`）。
换 16 kHz / 44.1 kHz / 单声道采集、甚至**同一块声卡自己录 + 放**都失败；而「单独播」「单独录」都正常。

**矩阵复测（同日，先停掉 pulseaudio 与 car_web.py 并确认无任何占用流）**：

| 组合 | 结果 |
|---|---|
| 单独采集：老无线麦（96 B/帧）/ 阵列麦（200 B/帧） | ✅ ✅ |
| **两路采集同时**（老麦 + 阵列麦） | ✅ 说明控制器**支持多个周期端点** |
| 单独播放（SPACETOUCH，600 B/帧） | ✅（干净状态下） |
| 采集 + 播放（老麦/阵列麦 × hw:/plughw × 换 Hub × 停 pulse/停 car_web） | ❌ **全部 -28 ENOSPC** |
| 同一块声卡自己录 + 放 | ❌ |

⇒ 不是软件抢占、也不是采样率/声道数的问题，而是**本板 xHCI 上「播放端点」和「任意采集端点」无法共存**；瓶颈落在那块声卡的播放端点（声明 600 B/帧，偏大）。**多端点本身没问题**，所以换一块「老实」的 USB 声卡（44.1 kHz S16 立体声 ≈ 176 B/帧）是否有机会**仍待实测**。
⇒ 现在能用的形态是**分时**：听（阵列麦）↔ 说（原声卡）切换，别指望边播边听。

> ⚠️ **调试注意**：连续硬试双流会把声卡打到 stall —— 之后 `aplay` 报 `-32 EPIPE`、`dmesg` 出 `can't set config #1, error -32`、声卡从 `arecord -l` 消失，**USB 重新授权/解绑重绑都救不回来，必须物理拔插**该声卡。

**可行的「边录边放」方案：播报不走 USB，走网络**（2026-11-05 实测通过）
- 板子跑 `bash run_py.sh tts_serve.py --port 8099`（网络喇叭），手机/PC 浏览器开 `http://<板子IP>:8099/listen` 当喇叭。
- 实测：**阵列麦连续采集 8 s = 384000 帧、零中断**，同一时间 TTS 合成 3 句（0.82~1.04 s/句）全部成功，`dmesg` 零 ENOSPC；`tts_serve` 健康检查显示 `alsa_playback_devices: 0` ⇒ **完全不占 USB 播放带宽**，与采集天然不冲突。
- 代价：声音从**手机/PC** 出来，不是从车上；但换来真正的全双工（播报期间麦克风一直在听）。
- 顺带结论：**显示器 HDMI 的 3.5 mm 口也没法用** —— 本板 HDMI 只有视频（内核无 `SND_SOC`/`SND_DESIGNWARE_I2S`，`/proc/asound` 里没有 HDMI/HDA 声卡，`aplay -l` 为空，显示器 EDID 读到 0 字节）。

> ⚠️ 仍**待验证**：① 带播放版本的模块或外接功放（接口 2/6）+ 回采（接口 4/5）能否让 AEC 生效；② 就算 AEC 生效，单设备是否仍撞 USB 周期预算；③ 12 方位在真实噪声/混响下的准确率。**不要当结论写进别的文档**。

⇒ 定位：**本版本不能靠它解决播报期失聪**；「单设备全双工」需换带播放的版本/外接功放再验，验证沿用《[现有设备全双工验证方案](现有设备全双工验证方案.md)》的口径。

## 七、排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `--list-ports` 列表为空 | 线没插 / 驱动没加载 / 权限 | `sudo dmesg \| tail`、`lsmod \| grep ch341` |
| 打开串口 `Permission denied` | 不在 `dialout` 组 | udev 规则已带 `MODE=0666`（`setup_qxmic_udev.sh`）；或临时 `sudo` |
| 收到的全是乱码 | 波特率不是 **1M** | `--baud 1000000`；确认没被 `stty` 改成 115200 |
| 有数据但一帧都解不出 | **TX/RX 接反**；或只接了 TX 没接 GND | 对调 TX/RX；**GND 必须共地** |
| 坐标乱跳 | 环境噪声、混响、风噪；声源太远 | 安静环境、≤8 m、人正对模组；多帧平滑后再用 |
| 方向整体偏一个固定角 / 左右镜像 | 安装朝向与车头不一致；坐标系顺逆时针约定相反 | `--offset` 补偿或软件取负，最终以 §8.2 标定为准 |
| 插 QXMIC 后小车串口连不上 | CH340 抢走了 `ttyUSB0` | 两个设备都 udev 固定（`ttyMIC` / `ttyCAR`），程序里不写 `ttyUSB0` |
| `arecord -l` 没多出声卡 | 只插了 TTL，**接口 1 没插**（模块没供电） | 接口 1 必须插：它同时负责供电与音频 |
| 灯环亮但 `ls /dev/ttyUSB*` 为空 | 只插了 USB（接口 1），**接口 3（TTL）没接线** | 自备 **USB-TTL（CH340/CH343）+ PH1.25 4pin 线**，只接 TX 与 GND、3V3 不接 |
| `aplay -l` 里没有这张卡 | **正常**：本模块 USB 侧只有采集端点 | 播报仍用另一块声卡/功放，见 §6.3 |
| 安静时录音几乎全 0 | **正常**：内置降噪把底噪压到 −85 dBFS 上下 | 别照搬普通麦阈值；按说话电平（−34 ~ −41 dBFS）标定 |
| 阵列麦在采集时，另一块声卡播不出来（`set_params` 失败 / `dmesg` `-28 ENOSPC`） | **本板同一条 USB 音频通道同一时刻只允许一路等时流**（2026-11-05 实测，换采样率/声道数/单设备都无效） | 分时切换：播报前停采集、播报后再开；详见 §6.3 |
| 经 USB Hub 后卡号从 0 变成 2，ASR 录不到/录错麦 | 插拔顺序变了，卡片索引会重排；且同时插两块麦时打分规则会选单声道那块 | 用 `--list-devices` 现看，`--device N` 或 GUI 下拉手动选 `DOV`，选一次会被记住 |
| 反复试双流后，声卡 `aplay` 报 **-32**、`can't set config #1`、甚至从 `arecord -l` 消失 | 失败的 `usb_set_interface` 把声卡打到 stall（EPIPE） | **物理拔插该声卡**（USB 重新授权/解绑重绑都救不回来）；调试时别连续硬试 |

### 8.2 「角度方向待真机标定」（上车后第一件事）

厂商只保证「方位号 ↔ 中心角」，**不保证装到车上后 0° 就是车头、正角是左还是右**。串口线接好后标定：

1. 车静止，人站在车头（约定 0°）喊话，记录 sector；再站到 90° / 180° / 270°（车左/后/右）各记一次，看左右是否镜像；
2. 整体偏差是**固定角度** → `--offset` 补偿；是**镜像** → 软件取负；实测表回填本文档（待补）。

> 精度提醒：**±15° / 12 档 30°** 只够回答「人在哪一侧」，不要拿它做精确角度伺服或替代碰撞检测。
