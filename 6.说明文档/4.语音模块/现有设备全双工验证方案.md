# 现有设备全双工验证方案（领夹麦 C 口 + 3.5mm 声卡）

> 适用：Atlas 200I DK A2 + 领夹麦（USB-C 接收器）+ 3.5mm USB 声卡 + 3.5mm 喇叭
> 日期：2026-10-19
> 目的：在不买新设备的前提下，判断能否把「采集 + 播放」合并到**同一块 3.5mm 声卡**上；
> 只有走不通时，才按第 8 节买最少的设备。

---

## 0. 结论先行

**大概率不用买新设备。** 你现在这块 3.5mm 声卡（USB-A + 3.5mm 输入 + 3.5mm 输出）
很可能已经是一块**同时具备播放和采集的单设备声卡**——它缺的不是「另一个 USB 设备」，
而是**一路模拟麦克风信号**。

两条零成本路径，按优先级：

| 路径 | 接线 | 成本 | 前提 |
|---|---|---|---|
| **A（优先）** | 领夹麦的**咪头**（3.5mm 插头）从发射器拔下 → 声卡 3.5mm 输入 | 0 元（可能需 5~10 元 TRS/TRRS 转接） | 咪头可拆、是 3.5mm 插头、声卡 mic 输入带偏置 |
| **B（次选）** | 接收器的 **3.5mm 输出** → 声卡 3.5mm 输入 | 0 元（可能需 10~20 元对录/衰减线） | 接收器除 C 口外还有 3.5mm 输出 |
| **C（兜底）** | 维持现状：接收器走 C 口 + 声卡走 USB-A | 0 元 | 两块设备能并发（**大概率不行**，先测） |

**只有 A、B 都不成立**（咪头不可拆 + 接收器只有 C 口），才需要买：

- **一根 3.5mm 有线领夹麦**（30~80 元）——最便宜，直接插声卡，单设备全双工；
- 或 **USB 会议全向麦**（200~400 元）——单设备 + 硬件 AEC，效果最好。

**不要买**：USB-C 转 3.5mm 无源转接头（不能把 USB 音频转成模拟）、第二块 USB 声卡
（又回到两块设备抢总线）、普通 USB hub（不增加带宽，且你已经实测 hub 上没声音）。

### 0.1 两种情况下的可行性结论

| 情景 | 可行性 | 成立条件 | 预期结果 / 成本 |
|---|---|---|---|
| **不买**（路径 A：咪头直插声卡） | ✅ 很可能可行 | 咪头可拆且是 3.5mm；声卡同卡有 `pcmXp`+`pcmXc`；mic 输入有 2~5V 偏置 | 单设备全双工，失聪窗口 0；可能只需 5~10 元 TRS/TRRS 转接 |
| **不买**（路径 B：接收器 3.5mm 输出） | ✅ 有输出口就可行的 | 接收器有 3.5mm 输出；声卡有 Mic/Line 输入 | 同上；line-level 可能需要 10~20 元衰减线 |
| **不买**（路径 C：维持两块 USB） | ⚠️ 大概率不可行 | 两块设备能在同一 xHCI 并发 | 基于 1660 次 `-28` 证据，概率低；只能当兜底 |
| **买一根 3.5mm 有线领夹麦** | ✅ 确定可行 | 声卡有 mic 输入 + 偏置 | 30~80 元；单设备全双工，最便宜的"确定能成" |
| **买 USB 会议全向麦** | ✅✅ 最稳 | 单设备、UAC 免驱、内置 AEC | 200~400 元；替掉三件套，失聪窗口 0 + 硬件 AEC |

## 1. 你现在到底有几块音频设备

| 设备 | 接口 | 在系统里的角色 | 关键事实 |
|---|---|---|---|
| 领夹麦接收器 | USB-C 插头 | **纯采集**（PCM2902，`08bb:2902`） | `lsusb -v` 只有 IN 端点，没有 OUT；它是一块**独立的 USB 声卡**，不是模拟输出 |
| 3.5mm 声卡 | USB-A + 3.5mm 输入 + 3.5mm 输出 | **播放 + 潜在采集** | 如果它同时枚举出 `pcmXp` 和 `pcmXc`，它就是我们要的「单设备全双工」 |
| 喇叭 | 3.5mm | 播放 | 接声卡 3.5mm 输出 |

> 🔴 **关键认知**：领夹麦接收器的 C 口是**数字 USB 音频**，不是模拟音频。
> 所以「C 口转 3.5mm」的无源转接头**不可能**把它接到声卡的 3.5mm 输入——
> 中间必须有一台「USB 主机 + DAC」，那是另一台设备，不是转接头。
> 真正能绕过接收器的，是**咪头本身**（模拟信号）。

> 🔍 **一个强线索**：项目之前枚举到一块 `SPACETOUCH USB Audio`，它**同时有播放和采集**
> （代码里因为"采集端没有真麦、RMS 0.0004"被降权成"音箱卡"）。
> 如果这块就是你的 3.5mm 声卡，那 `pcmXp` + `pcmXc` 已经存在——
> 你只需要把咪头插进它的 3.5mm 输入，单设备全双工的硬件条件就齐了。

## 2. 第一步：5 分钟物理检查（不用接板子）

### 2.1 检查领夹麦

把领夹麦拿出来，看三件事：

1. **咪头能不能从发射器上拔下来？** 大多数无线领夹麦的咪头是一根 **3.5mm 插头**插在发射器上。
2. 咪头插头是 **TRS（3 段）** 还是 **TRRS（4 段）**？
3. **发射器/接收器上有没有 3.5mm 输出孔**（有的型号叫 LINE OUT / 监听孔）？

| 现象 | 判定 | 走哪条路 |
|---|---|---|
| 咪头可拆，且是 3.5mm 插头 | ✅ 可以直插声卡 | **路径 A** |
| 咪头不可拆，但接收器有 3.5mm 输出 | ✅ 可以接声卡 | **路径 B** |
| 咪头不可拆，接收器只有 C 口 | ❌ 没有模拟输出 | **路径 C 或购买** |

### 2.2 检查 3.5mm 声卡

1. 3.5mm 输入口旁边印的是 **Mic** 还是 **Line In**？
2. 有没有 **Mic / Line 切换开关**？
3. 声卡插到板子上后，`arecord -l` 和 `aplay -l` 是否出现**同一张 card** 的 `pcmXc` 和 `pcmXp`？

| 现象 | 判定 |
|---|---|
| 输入标 **Mic**，且同一 card 有 `pcmXc` + `pcmXp` | ✅ 最理想，直接走路径 A |
| 输入标 **Line In**，同一 card 有 `pcmXc` + `pcmXp` | ⚠️ 可以，但接收器/咪头信号可能太小或过载，需要衰减/前置放大 |
| 只有 `pcmXp`，没有 `pcmXc` | ❌ 这块声卡不能采集，路径 A/B 都不成立 |

> 这一步不用猜：板子连上后跑 `arecord -l; aplay -l` 就知道。
> 如果两张卡都在，**先拔掉领夹麦接收器**，只留声卡，避免自动选设备选错。

## 3. 路径 A：咪头直插声卡（0 元，优先）

### 3.1 接线

```text
领夹麦咪头（3.5mm TRS/TRRS）
        │
        ▼
┌─────────────────────┐
│ 3.5mm USB 声卡       │
│  [3.5mm 输入] ← 咪头 │
│  [3.5mm 输出] → 喇叭 │
│  [USB-A] → 开发板    │
└─────────────────────┘
```

**接线要点：**

- 声卡 USB-A **直插开发板**，不要过拓展坞（你已经实测 hub 上没声音）；
- 喇叭接声卡的 **3.5mm 输出**；
- 领夹麦接收器**先拔掉**，避免系统把它当成默认麦克风；
- 咪头插声卡的 **3.5mm 输入**，插到底（有些插座有卡扣）。

### 3.2 设置增益

```bash
# 先看声卡号（假设是 card 1）
arecord -l

# 打开混音器：把 Mic Capture 拉到 100%，有 Mic Boost 就打开
alsamixer -c 1
# 或命令行：
amixer -c 1 sset 'Mic Capture' 100% cap 2>/dev/null
amixer -c 1 sset 'Mic' 100% cap 2>/dev/null
amixer -c 1 sset 'Mic Boost' 100% 2>/dev/null
```

> ⚠️ 很多免驱声卡的 Mic 增益默认是 **0%**（PCM2902 就是），不拉满会录到全底噪。
> 如果 `alsamixer` 里只有 `Line` 没有 `Mic`，说明这块声卡的输入是 line-level，
> 咪头直插会太小——见 3.5 的失败处理。
> 另外把 **AGC / 自动增益 / 降噪 / 回声消除** 都关掉（如果有）：
> KWS 靠稳定的能量分布判阈值，AGC 会把远处噪声也泵上来，导致误触发。

> 💡 手头没有可拆的咪头？先用任何一根 **3.5mm 有线耳麦** 插声卡 mic 输入测一遍。
> 只要能录到人声，就证明声卡的输入通路是好的，剩下只是「用哪根麦」的问题。

### 3.3 录音测试

```bash
# 录 5 秒，终端直接看电平条
arecord -D plughw:1,0 -f S16_LE -r 48000 -c 1 -d 5 -V mono /tmp/mic_a.wav
```

对着咪头正常说话（距离 15~25 cm）。

| 预期现象 | 判定 |
|---|---|
| 电平条随说话明显起伏，峰值到 40%~70% | ✅ 通过 |
| 回放 `/tmp/mic_a.wav` 清晰、无严重底噪 | ✅ 通过 |
| 电平条几乎不动（< 5%） | ❌ 无声：声卡没提供偏置 / 插头不匹配 / 增益没开 |
| 声音发闷、很小，但能听到 | ⚠️ 偏置不足或阻抗不匹配，考虑 TRS/TRRS 转接或换麦 |
| 削顶、破音 | ❌ 输入是 line-level 或增益过大，需衰减 |

### 3.4 量化判定（脚本会算）

| 指标 | 通过线 | 说明 |
|---|---|---|
| 说话 RMS | **≥ 0.01**（约 -40 dBFS） | 正常说话通常在 0.02~0.15 |
| 静音 RMS | **< 0.003** | 底噪过高会影响 KWS |
| 峰值 | **< 0.98** | 不削顶 |
| 50 Hz 工频哼声 | 无明显 | 有的话多半是接地/屏蔽问题 |

### 3.5 如果失败：先别买，做这两个 5 分钟排查

1. **换 TRS/TRRS 转接头**（5~10 元）：
   声卡的 mic 输入如果是 **TRRS（CTIA）**，而咪头是 **TRS**，直插可能把 mic 短接到地。
   反之亦然。两种都试一次，哪种有声音用哪种。
2. **量偏置电压**（万用表直流档）：
   声卡 mic 输入的 **tip/ring 对 sleeve** 应有 **2~5 V** 的 plug-in power。
   量不到电压 → 这块声卡不给驻极体供电，咪头直插不会工作。
   → 换 **电池供电的领夹麦**，或买一块带 mic bias 的声卡（见第 8 节）。

## 4. 路径 B：接收器 3.5mm 输出 → 声卡输入（0 元，次选）

### 4.1 接线

```text
领夹麦接收器 [3.5mm 输出 / LINE OUT]
        │  3.5mm 对录线
        ▼
声卡 [3.5mm 输入] → [3.5mm 输出] → 喇叭
        │
     USB-A → 开发板
```

### 4.2 关键注意

- 接收器输出多半是 **line-level 或耳机电平**，声卡输入是 **mic-level** → 可能过载。
  **先把接收器音量调到最低**，再一点点开大；
- 如果声卡有 **Mic / Line 开关**，选 **Line**；
- 如果只有 Mic 档且一开就削顶，需要一根 **10~20 dB 衰减线**（或自己焊两个电阻），
  10~20 元；
- 有些接收器要在菜单里把输出切到 **3.5mm / USB**，否则 3.5mm 口没信号。

### 4.3 预期与判定

| 现象 | 判定 |
|---|---|
| 说话电平明显、不削顶、回放清晰 | ✅ 通过 |
| 一说话就削顶/破音 | ⚠️ 加衰减线，或把接收器音量降到 20% 以下 |
| 完全没信号 | ❌ 检查接收器输出是否启用；换一根对录线 |
| 有持续嗡嗡声 | ⚠️ 接地环路，换屏蔽更好的线或加隔离 |

## 5. 路径 C：维持两块设备（不推荐，但先测）

如果你暂时不想动接线，就先跑 `audio_duplex_probe.sh`，看两块设备有没有**任何**并发组合能成功：

```bash
cd ~/car_gui
bash audio_duplex_probe.sh
```

重点看：

- **先播后录 / 先录后播** 两组矩阵是否全红；
- `dmesg` 是否有 `-28`；
- 同卡全双工（如果声卡自己有 `pcmXp`+`pcmXc`）是否成功。

| 结果 | 结论 |
|---|---|
| 所有并发都失败 | 两块设备路线不可行，回到路径 A/B |
| 某个低采样率组合成功 | 可以先用该组合，但稳定性存疑，仍建议 A/B |
| 同卡全双工成功 | ✅ 直接走 A/B，不用再折腾两块设备 |

> 你的声卡在 hub 上没声音，说明这块板子的 USB 音频对拓扑很敏感。
> 两块设备即使能勉强并发，也不建议作为长期方案。

## 6. 决定性测试：单设备同时录放

**这是整个方案的核心。** 只有在**同一块声卡**上同时播放和采集都成功，才算真正全双工。

### 6.1 接线

按路径 A 或 B 接好：咪头 → 声卡输入，喇叭 → 声卡输出，声卡 USB-A → 板子直插。

### 6.2 命令

```bash
# 终端 1：播放 3 秒测试音
aplay -D plughw:1,0 /path/to/tone.wav

# 终端 2：同时从同一块卡录 3 秒
arecord -D plughw:1,0 -f S16_LE -r 48000 -c 1 -d 3 /tmp/duplex.wav
```

> 设备号以 `aplay -l` / `arecord -l` 为准；同一张卡可能播放是 `plughw:1,0`、
> 采集是 `plughw:1,0` 或 `plughw:1,1`，用 `mic_input_probe.sh` 会自动取。

### 6.3 预期与判定

| 现象 | 判定 |
|---|---|
| `aplay` 正常出声，`arecord` 同时录到文件（非空） | ✅ **单设备全双工成立** |
| `aplay` 报 `set_params:1416` | ❌ 播放被采集挡住 |
| `arecord` 报 `-9999` / `Input/output error` | ❌ 采集被播放挡住 |
| 两个都成功，但录音里全是喇叭回声 | ⚠️ 功能成立，但需要 AEC/声学隔离（见主方案 5.3/5.4） |

**脚本先跑 5 次做筛查；正式验收重复 20 次，成功 ≥ 19 次才算稳定。**

### 6.4 如果这一步失败

说明这块板子的 xHCI 连「单设备同时 IN+OUT」都不允许。此时：

- 优先换 **USB 会议全向麦**（单设备 + 硬件 AEC，HS 优先）；
- 或走 **网络音箱旁路**（`tts_serve` → 手机浏览器），把播放从板子 USB 上彻底移走；
- 或考虑 **M.2 转 USB 控制器**（不推荐优先，见主方案 4.4）。

## 7. 判定表（一张表看完）

| 检查 | 通过 | 失败含义 | 下一步 |
|---|---|---|---|
| ① 咪头可拆 / 有 3.5mm 插头 | 是 | 没有模拟输出 | 走路径 B 或购买 |
| ② 接收器有 3.5mm 输出 | 是 | 只有 C 口 | 走路径 A 或购买 |
| ③ 声卡同卡有 `pcmXp`+`pcmXc` | 是 | 声卡不能采集 | 换带 mic 输入的声卡 |
| ④ 声卡 mic 输入有 2~5V 偏置 | 是 | 不能供驻极体麦 | 换电池麦 / 换声卡 |
| ⑤ 说话 RMS ≥ 0.01、静音 < 0.003 | 是 | 无声/底噪大 | 查增益/接线/偏置 |
| ⑥ 同卡同时录放 20 次 ≥ 19 成功 | 是 | 单设备也不能全双工 | 换会议全向麦 / 网络音箱 |
| ⑦ KWS + TTS 并行，播报中喊停 19/20 | 是 | 软件/AEC 未调好 | 按主方案 5.3/5.4 调 |

**①~⑥ 全绿 → 不需要买任何新设备，直接进软件改造（主方案第 5 节）。**

> ⚠️ **硬件全绿 ≠ 软件自动生效**：当前代码在每次播报前仍会 `pause()` KWS。
> 必须同时按主方案 5.2 打开 `CAR_AUDIO_DUPLEX`、让 `_pause_kws_for_playback` 短路，
> 失聪窗口才会真正变成 0。否则硬件能并行，软件还是主动让位。

## 8. 如果必须买：类型与关键参数（不指定品牌）

### 8.1 最便宜：3.5mm 有线领夹麦（30~80 元）

| 参数 | 要求 |
|---|---|
| 类型 | 驻极体电容、全指向 |
| 插头 | 3.5mm **TRS 或 TRRS**，与声卡输入匹配（买前确认） |
| 供电 | **需要 plug-in power（2~5V 偏置）**；先确认声卡有偏置，否则买**电池供电**款 |
| 线长 | 1.5~2 m |
| 附件 | 防风棉、领夹 |

> 这是「路径 A 的直接替代」：咪头不可拆时，买一根有线麦直接插声卡，
> 声卡就是单设备，问题从「两块 USB 设备」变成「一块设备 + 一根模拟线」。

### 8.2 效果最好：USB 会议全向麦（200~400 元）

| 参数 | 要求 |
|---|---|
| 设备形态 | **单 USB 音频设备**：一个 `lsusb` 节点、一个 ALSA card、同时有 `pcmXp` + `pcmXc` |
| 协议 | UAC 1.0 / 2.0，Linux 免驱（`snd-usb-audio`） |
| 采样率 | 16 kHz 采集 / 48 kHz 播放 |
| 关键能力 | **内置硬件 AEC**、降噪、麦克风阵列 |
| 扬声器 | 音量足够覆盖小车周边 1~2 m |
| 供电 | USB 总线供电或自带电源 |
| 速率 | **480M 优先**；单设备 12M 也可先试 |

> 它同时替掉「领夹麦接收器 + 3.5mm 声卡 + 喇叭」三件套，
> 从根上消除两块 USB 设备抢总线，且硬件 AEC 比软件 AEC 稳。

### 8.3 只换声卡：带 mic 偏置的 USB 声卡（40~80 元）

| 参数 | 要求 |
|---|---|
| 设备形态 | **单设备**，同时有 `pcmXp` + `pcmXc`；不要「一拖二」 |
| 协议 | UAC 1.0，Linux 免驱 |
| 输入 | 3.5mm **Mic 输入，带 plug-in power（2~5V）**；有 Mic Boost 更好 |
| 输出 | 3.5mm 立体声输出 |
| 采样率 | 48 kHz |
| 速率 | 480M 优先 |

> 只有当你现在的声卡「没有 mic 偏置」或「mic 输入底噪太大」时才需要换这块。

### 8.4 不要买

| 东西 | 为什么不要买 |
|---|---|
| USB-C 转 3.5mm 无源转接头 | C 口是数字 USB 音频，无源头不能转成模拟 |
| 第二块 USB 声卡 | 又变成两块设备抢同一条 USB 总线 |
| 普通 USB hub | 不增加上游带宽；你已经实测 hub 上没声音 |
| 「一拖二」无线麦接收器 | 通常枚举成两块 USB 音频设备，等于把问题复制一遍 |

## 9. 为什么「不买」也可能成立（原理）

你的 3.5mm 声卡内部大概率是这样：

```text
USB-A ── USB Audio Class 设备 ──┬── DAC → 3.5mm 输出 → 喇叭
                                └── ADC ← 3.5mm 输入 ← 咪头
```

**播放和采集在同一块芯片、同一套 USB 配置里**。只要 3.5mm 输入有信号，
它就是「单设备全双工」——正是主方案要的东西。

你之前的失聪问题，是因为采集走的是**另一块** USB 声卡（领夹麦接收器），
两块设备抢同一颗 xHCI。把采集换到这块 3.5mm 声卡上，问题就从「两块设备」
变成「一块设备」，冲突面大幅缩小。

**唯一的未知数**是：这块声卡的 3.5mm 输入是不是 mic-level、有没有 plug-in power。
第 3 节的录音测试就是验这个。

## 10. 板子连上后我会跑的脚本

新增 `car_gui/mic_input_probe.sh`（只读 + 录音，不改配置）：

```bash
cd ~/car_gui
bash mic_input_probe.sh
# 指定声卡号：
CARD=1 bash mic_input_probe.sh
```

它会：

2. 打印 `amixer` 控件（看有没有 Mic / Mic Boost / Line）；
3. 把 Mic 增益拉到 100%、打开 Mic Boost（尽力而为）；

5. 在同一张卡上做 **3 秒播放 + 3 秒采集** 的并发测试；
6. 输出 PASS/FAIL 和建议。

配套的 `audio_duplex_probe.sh` 仍然保留，用来测「两块设备」的并发矩阵。

## 11. 需要你先确认的 4 件事

板子连上之前，麻烦先看一眼：

1. **领夹麦的咪头能不能从发射器上拔下来？** 插头是 3 段（TRS）还是 4 段（TRRS）？
2. **接收器除了 C 口，有没有 3.5mm 输出孔？**
3. **3.5mm 声卡的输入口印的是 Mic 还是 Line In？有没有 Mic/Line 开关？**
4. 声卡插上板子后，`arecord -l` 和 `aplay -l` 里是不是**同一张 card** 同时有 `pcmXc` 和 `pcmXp`？

这 4 个答案决定走 A / B / 购买哪条路。你连上板子后告诉我，我直接跑脚本出结论。
