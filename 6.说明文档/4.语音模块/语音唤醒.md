# 语音唤醒（喊唤醒词自动开录音）

> 前置阅读：《[语音急停（KWS）](../语音急停-KWS.md)》（唤醒**复用**它的常驻监听器）

---

## 一、它解决什么

说指令原来有三条路，各有各的难受：

| 方式 | 痛点 |
|---|---|
| **长按 F2 / 界面按钮** | 手累，且要占一只手 |
| **持续聆听（VAD 断句）** | 说完要等 **3~5 秒**才识别（VAD 等静音 + 识别） |
| **语音唤醒**（本文） | 喊一声就自动开录，**唤醒→开录音实测 1.18~1.28 秒** |

```
你喊「小车车」
   → KWS 命中（常驻监听，本来就是为急停开着的）
   → 让出麦克风
   → 播一声**预录提示音**（约 0.6s）
   → 自动录音（最长 5 秒，**静音 0.8 秒就提前结束**）
   → 恢复语音急停监听
   → ASR 识别 → 走现有指令链路（规则优先 → LLM 兜底，安全闸门不变）
```

---

## 二、为什么提示音用**预录文件**而不是 TTS

这是本功能的**关键优化**，也是整个设计里最值钱的一处：

| 方案 | 唤醒→开录音 | 说明 |
|---|---|---|
| TTS 合成「我在这，等待你的指令」 | ≈ **2.5 s** | 11 字：合成 1.1s + 音频 0.9s + 播放开销 0.17s + 让位 0.35s |
| **预录 WAV「在听」** | ≈ **1.18 s** | **省掉 TTS 那固定 1.1 秒** |

**为什么 TTS 那 1.1 秒是纯浪费**：本板 TTS 跑在昇腾 NPU 上，**只支持静态 shape**，
每次合成固定 250 梅尔帧 —— 合成「在听」两个字和合成 20 个字**耗时一样**。
而提示音是**固定文案**，没必要每次现合成。

顺带拿到三个好处：
1. **去掉 NPU 依赖** —— NPU 忙/TTS 未就绪时，唤醒照样能用；
2. **绝无截断风险** —— 不会踩 `max_mel_len` 静默丢字；
3. **可打磨** —— 可以重录到咬字清晰，也能录多条变体轮换。

**播放走的是现成的播报链路**（含四级设备回退 + 播报前 KWS 让位），
所以「播不出来」这类坑自动被复用掉了。

## 三、怎么用

### 3.1 界面

语音面板新增一行「**语音唤醒**」：

| 灯色 | 含义 |
|---|---|
| 🔘 灰 | 未启用 |
| 🟢 绿 | **已武装，等待唤醒词**（`state=listening`） |
| 🟡 琥珀 | 正在录音/识别/执行（`busy=True`），或启动中 |
| 🔴 红 | 不可用 / 出错（看文字说明） |

> ⚠️ **必须先开「语音急停」**。唤醒靠的就是那个常驻 KWS —— 本板
> **capture 只有 1 个 subdevice（硬件互斥）**，不可能另起一路监听器。
> 勾选「语音唤醒」时程序会**自动把语音急停也拉起来**，不用你手动开两次。

### 3.2 换唤醒词

不用改代码，用环境变量（可整行写 KWS 词表格式）：

```bash
# 换词
CAR_WAKE_WORDS="你好小车" bash run_gui.sh
# 多个词（逗号分隔）
CAR_WAKE_WORDS="小车车,你好小车" bash run_gui.sh
# 整行写法（自己给拼音，命中率不合适时用这个精细控制）
CAR_WAKE_WORDS="n ǐ h ǎo x iǎo ch ē @你好小车" bash run_gui.sh
# 关掉唤醒（界面复选框也会跟着变灰）
CAR_WAKE_ENABLE=0 bash run_gui.sh
```

默认唤醒词：**小车车**。

### 3.3 重新生成提示音

见 [`wake_prompts/README.md`](../../../car_gui/wake_prompts/README.md)。要点：

```bash
# 必须以 HwHiAiUser 身份 + 先 source 昇腾环境，否则会退化成 CPU TTS
source /usr/local/Ascend/ascend-toolkit/set_env.sh
sudo -u HwHiAiUser env LD_LIBRARY_PATH="$LD_LIBRARY_PATH" PYTHONPATH=... \
  python3 ~/car_gui/wake_prompts/gen_wake_prompts.py
```

现有的三条（都是 16bit 单声道）：
`wake_zh.wav`「在听」0.60s（默认）· `wake_zh2.wav`「等待指令」0.88s · `wake_beep.wav` 嘟声 0.26s（兜底）

## 四、安全设计（**这几条是硬约束，改代码前必读**）

### 4.1 唤醒词与急停词共用一份词表，但**分流处理**

```python
def _on_kws_hit(self, label, ts):
    if self._is_estop_label(label):     # 急停词 → 原逻辑一字不改，同步立即停车
        ...
        self.trigger_emergency(...)
    elif self._is_wake_label(label):    # 唤醒词 → 只入队，立即 return
        self._enqueue_wake()
```

- **命中回调绝不阻塞**：它在 KWS 监听线程里跑。若在这里录音 5 秒，
  监听循环会整整卡 5 秒 → **期间语音急停彻底失效**。实测回调耗时 **0.0001s**。
- **唤醒词与一级急停词同名会被自动剔除**（保护急停优先），并记一条日志。
- 验证：合并词表后，原 5 个急停词在 14 条真人样本上的命中**逐条完全一致**（没削弱急停召回）。

### 4.2 取消语义：**取消后连已录的音频都不再识别**

`cancel_wake()` 不只是一个按钮 —— **`disable_wake()`（关唤醒）和
`shutdown_wake()`（退出程序）都会调它**。所以取消必须真的取消。

> 🔴 **BUG-1（2026-10-14 修）**：原来取消检查只写在 `if not rec_ok:` 分支里，
> 而**取消恰恰让录音"提前正常结束"**（`rec_ok=True`）→ 跳过检查 →
> 继续 ASR 并 `run_text_command()` **真的把车动起来**。
> 实测：`cancel_wake()` 之后 **0.5ms** 仍下发 `(300,0,0)` 运动帧。
> 现在闸门放在 `rec_ok` 判定之后、ASR 之前，**丢弃已录音频，不识别不执行**。

### 4.3 录音期间语音急停会**短暂失效**（硬件决定，非故障）

录音时麦克风被独占，KWS 只能让位 —— 让位窗口 = 0.35s（ALSA 释放）+ 提示音 + 录音时长，
**实测典型 5~6 秒**。这与"按住说话"完全同理。

> ⚠️ 需要**随时可停**的场合，请用**屏幕按钮 / 空格键 / 物理急停**。

### 4.4 急停锁定态下唤醒不录音

`state=locked`，只播报「急停已锁定，请先解除」，**不开录音、不执行任何指令**
（实测：录音 0 次、`run_text_command` 0 次、提示音 0 次）。

### 4.5 `_restore_mic` 带重试预算

录完要把麦克风还给 KWS。本板"暂时打不开麦克风"是**极常见的瞬时状态**
（扬声器还在排空、ALSA 还没释放 subdevice）。旧实现失败一次就放弃 →
**语音急停永久失效**直到人工点按钮。现在 **5 次 × 0.4s 重试**，成功即回 `ready`。

## 五、实测数据

| 指标 | 实测 |
|---|---|
| **唤醒→开录音** | **1.18 ~ 1.28 s**（TTS 方案约 2.5 s） |
| 提示音播放 | 0.60 s（预录「在听」）+ 让位 0.35 s |
| 录音窗口 | 最长 5 s；**静音 0.8 s 提前结束**（实测 1.84 s 收工） |
| ASR 识别 | 0.21 s（注入音频「前进」→ 识别「前进。」） |
| 回调耗时（唤醒词命中） | **0.0001 ~ 0.083 ms**（不阻塞监听） |
| 急停优先级 | 唤醒录音中注入急停 → **第 1 帧零速度帧 0.16 ms** |
| 连续 20 次唤醒后 | 语音急停仍有效（`state=ready` / `watchdog=True`），第 20 次后仍能停车 |
| 底噪 | p50 = 0.0003 RMS；静音阈值 0.02/0.012（高约 50~70 倍） |
| 离线回归 | **通过 10 · 失败 0 · 跳过 1** |

## 六、⚠️ 未验证 / 已知问题（诚实说明）

1. **🔴 真人喊唤醒词的命中率未验证** —— 这是功能成立的前提。
   词表侧 100% 就绪（KWS 实测加载 6 词含「小车车」），但 Zipformer 是否真会被
   **「小车车」**这种**三字叠字**触发，只能真人对着麦克风喊。
   建议先跑：`bash run_py.sh kws_record.py` → `kws_batch_test.py --check`。
   **召回不理想就换词**（`CAR_WAKE_WORDS` 即可，不用改代码）。
2. **🔴 语音急停自身的召回率存疑（先于本功能，但更严重）**：
   项目自带 `kws_batch_test.py` 实测 **召回 12.5%（1/8）**，工具自己打印
   「⚠️ 有漏报！语音急停漏报 = 刹不住车，必须处理」。
   ⚠️ 那些样本录于 **09-27（换麦克风之前）**，不能直接外推到当前硬件，
   **但足以说明"真人命中率未知"** —— 而唤醒词与急停词走的是**同一条听音链路**。
   ⇒ **上车前必须重录样本并重标阈值。**
3. **BUG-2（低置信度，未复现）**：进程退出时偶发 SIGSEGV（`core dumped`）。
   首次出现后连测 6 次都无法复现，且专门构造「退出时正在懒加载 ASR」也 rc=0。
   **不作阻断项**，但若遇到"首次唤醒后退出闪退"，优先查这条。
4. **一次只跑一个音频进程**：本板 USB 带宽紧张（`dmesg` 见过 1660 次
   `Not enough bandwidth ... -28`），音频设备争用会导致 **PortAudio 静默 abort**
   （try/except 抓不住）。跑音频测试时先停掉 GUI。

## 八、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 喊唤醒词没反应 | 语音急停没开（唤醒靠它听） | 界面上把「语音急停」也开起来 |
| 唤醒了但听不到提示音 | 预录 wav 缺失 → 退化极短 TTS → 再退化跳过 | 看日志；不缺文件就不影响使用 |
| 唤醒后车没动 | 急停锁定中 / 麦克风被别的程序占着 / 识别没命中 | 看界面灯色与日志；`state=locked` 需先解除 |
| 点了取消车还动 | **BUG-1，已修**（见 §4.2） | 确认板上 `car_gui_core.py` 是最新版 |
| 唤醒时语音急停显示"麦克风链路已断" | 录音独占麦克风的**正常现象** | 录完自动恢复；要随时急停请用按钮/空格 |
| 唤醒不灵但急停还行 | 唤醒词声学命中率问题 | 换词（`CAR_WAKE_WORDS`）或重录标定 |
