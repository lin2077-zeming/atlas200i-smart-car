### 2.3 实测新增：板子**完全没有音频硬件**

这是本次最重要的硬件发现，比之前"只有 1 个板载 MIC"的结论**更严重**：

```
$ cat /proc/asound/cards
--- no soundcards ---
$ arecord -l
arecord: device_list:274: no soundcards found...
```

内核配置揭示了根因：

```
# CONFIG_SND_DESIGNWARE_I2S is not set      ← I2S 总线驱动未编译
# CONFIG_SND_SIMPLE_CARD is not set         ← 简单声卡驱动未编译
# CONFIG_SND_AUDIO_GRAPH_CARD is not set    ← ASoC 音频图未编译
```

**结论：官方内核根本没有编译板载音频子系统**，所以：

- ❌ **板载 MIC 用不了**（不是没插好，是内核没驱动）
- ❌ HDMI 音频也没有可用声卡注册（`drv_hdmi` 报 `check_audio_attr fail`）
- ✅ **唯一出路是 USB 声卡**，而 `CONFIG_SND_USB_AUDIO=y` **已编译进内核 → 插上即用，无需装驱动**

> **对采购清单的影响**：`../3.硬件与供电/采购清单.md` 里"USB 声卡必配"这一条要从"⚠️ 必配"**升级为"🔴 最关键、缺了整个语音闭环直接断掉"**。
> `asr_engine.py` 在无输入设备时的降级行为**很优雅**（返回 `None` 而不是崩溃），这点已验证。

## 三、发现并修复的 Bug

### 3.1 🔴 `car_gui_pyside.py` 启动必崩（严重）

**这是本次唯一的代码 bug，且是致命级——GUI 根本起不来。**

```

  File "/home/HwHiAiUser/car_gui/car_gui_pyside.py", line 89, in <module>

```

**根因**：QSS 模板字符串里用了 `%(green)s`（共 4 处），但格式化字典里漏了这个键。

```python
# 修复前：7 个键，模板引用了 8 个
""" % {"bg": C_BG, "panel": C_PANEL, "border": C_BORDER, "text": C_TEXT,
       "muted": C_MUTED, "blue": C_BLUE, "danger": C_DANGER_FILL}

# 修复后：补上 green
""" % {"bg": C_BG, "panel": C_PANEL, "border": C_BORDER, "text": C_TEXT,
       "muted": C_MUTED, "blue": C_BLUE, "green": C_GREEN, "danger": C_DANGER_FILL}
```

**为什么之前没发现**：
- 本机没有 PySide6，`selftest_offline.py` 不 import GUI 模块 → 测不到
- 报错发生在**模块加载期**（第 89 行），不是运行期 → 连窗口都创建不出来
- `%` 格式化是**运行时**求值 → 静态检查（`py_compile`）看不出来

**验证**：修复后 GUI 稳定运行 19 分钟，内存 118MB 无泄漏，CPU 占用 8~10%。

> **教训**：这类"模板键缺失"错误应该在 `selftest_offline.py` 里加一条断言覆盖——**导入 GUI 模块本身**就是一次有效检查。

### 5.1 ⭐ 声卡到货前的环境预置（本轮追补，2026-09-26）

**问题**：板子没有音频硬件 → ASR 的真机录音被卡住。但**除了"真的用麦克风录音"，
其余环节全都可以提前做完**。本轮把这条链路补齐了。

**新增能力（`asr_engine.py`）**：

- `synthesize_test_wav()` —— 从模型自带的官方 `test_wavs` 裁一段 2.5 秒音频，
  生成标准 16bit PCM 单声道 wav。
- `--synthetic-selftest` 命令行入口。

**为什么这招有用**：它喂给 `recognize(16000, samples)` ——
**也就是真实录音走的一模一样的代码路径**。这样能在没有麦克风的情况下，
提前排掉采样率、位深、声道、重采样、静音裁剪**一整类**问题。

**新增脚本 `asr_preflight.py`（L0~L6 分层体检）**：

| 层 | 检查内容 | 是否需要声卡 | 实测 |
|---|---|---|---|
| L0 | numpy / sounddevice / sherpa-onnx / PortAudio | ❌ | ✅ 全 OK |
| L1 | ALSA 声卡注册 + 设备枚举 + 工具链 | ✅ **需要** | ⏳ 0 个设备 |
| L2 | 模型 3 个文件 + 大小合理性 | ❌ | ✅ 228.2/0.3/0.6 MB |
| L3 | 引擎加载耗时 + VAD 模式 | ❌ | ✅ 5.47s / silero |
| L4 | 识别官方音频 + RTF | ❌ | ✅ RTF 0.155 |
| L5 | **合成音频闭环**（录音路径契约） | ❌ | ✅ 0.44s |
| L6 | 指令解析（纯函数，不碰串口） | ❌ | ✅ 18/18 |

**实测汇总**：

```
通过 16 · 硬失败 0 · 待硬件 2
⏳ ALSA 声卡注册  无（no soundcards）
⏳ 录音设备数量   0 个
✅ 除声卡外，ASR 环境已全部就绪。
```

> **退出码设计**：声卡未就绪记为"待硬件"（soft），**不计入失败**。
> 所以「硬失败 = 0」就是环境侧无遗留问题的判据。
> 声卡到货后重跑，L1 自动从 ⏳ 变 ✅ —— **当天即可直接进语音控车**。

**一个有意思的观测**：L5 的合成片段识别成「**开放**时间早上9」（正确），
而 L4 识别**完整**音频时是「**开饭**」。说明 int8 的误差与音频长度/上下文有关 ——
这进一步印证了 `parse_text_command()` 必须保持 `in` 宽松匹配的设计判断。
